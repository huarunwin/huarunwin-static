honk

开源代理内核 · 亦称 daeuniverse/honk / honk-core / honk 内核

honk 是 daeuniverse 组织发布的 Rust Linux 透明代理引擎：用 TC eBPF 和隔离的 dae0/daens 数据路径接管 LAN 转发与主机流量，再按 dae 语法的路由规则、节点组和 DNS 选择出站。它适合愿意在 Linux 6.12+ 网关或主机上试用新内核的用户；官方当前仍标为 early alpha，不应当作生产稳定方案。

内核介绍

以下章节展开解释各项能力的实际机制；快速事实总览见上方「内核能力」矩阵。

TC eBPF 数据路径如何接管流量

honk 可以分别配置 LAN 接口与 WAN 接口，处理从局域网转发进来的流量以及主机自身发起的流量。TC eBPF 入口先按控制面、本地服务和连接状态做判断，再根据编译后的路由结果选择直连旁路或代理重定向；代理路径经过独立的 dae0/daens 网络命名空间和透明监听器。这个数据路径解释了它为什么面向 Linux 主机、网关和路由器，也说明它不是一个给桌面应用提供系统代理按钮的跨平台客户端。

节点、订阅、组与规则怎样串起来

配置可以用 node 块登记带标签的分享链接，用 subscription 块拉取并合并节点，再在 group 块里用过滤条件组织候选。Selector、URLTest、LoadBalance、Fallback 和 Score 分别提供手动选择、按探测结果选择、分配连接、故障回退和基于观测的评分策略；routing 规则随后把域名、地址、进程或端口等条件交给某个组、direct 或 block。规则指定的是处理出口，组策略才决定组内的具体节点，因此更换组内节点不必重写每条规则。

DNS、出站协议与 FakeIP 边界

honk 的 DNS 上游覆盖 UDP、TCP、DoT、DoH、DoQ 和 DoH3，查询可以按 DNS 路由经直连、节点或组发送，并保留请求与响应路由及缓存配置。代理出站包括 SOCKS5、Shadowsocks/2022、Trojan、AnyTLS、Hysteria2、TUIC、Juicity、VMess 和 VLESS，部分协议还带有 H2 XHTTP 形态；协议参数和限制仍要按对应节点配置核对。项目明确没有 FakeIP 引擎，也没有声称与 mihomo 完全兼容，因此不能把其他内核的配置字段直接套过来。

查看来源

发行构建与 Linux 前提

官方发行包面向 x86_64 和 aarch64 Linux，full 构建同时提供原生 API、Clash API 与内嵌 doona，native-api 和 clash-api 是功能更窄的变体；musl 包用于静态部署，full 另有 glibc 变体。真实透明数据面要求 root、Linux 6.12+、对应的 BPF/TC/cgroup 内核能力和 bpffs；普通 cargo build --release 不会内嵌真实 eBPF 数据面。README 还明确没有 Windows 或 macOS 数据面，所以这些平台不能按桌面客户端的方式登记。

查看来源

控制接口、Alpha 状态与许可

honk 提供 dae 配置语法、重载、honk-tool，以及可选的原生 API 和 Clash 兼容 REST/WebSocket API；doona 或 zashboard 是另行连接这些接口的网页面板。官方 README 将项目标为 early alpha，版本说明也规定 v1.0 以前的次版本可能改变配置或行为；截至本次核验，GitHub 没有可接受的稳定 Release，v0.1.0-beta.6 仍是预发布。因此本条目记录能力和边界，不能把它当作生产稳定版或把 beta 版本写入稳定版本栏。源码采用 GPL-3.0-only。
