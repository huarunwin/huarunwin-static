Nakis

开源代理内核

Nakis 是 nyarvex 编写的 Go 代理协议参考实现，在一个程序中提供本地 SOCKS5 客户端和远端服务端。它通过预建连接与业务结束后的顺序复用，把后续目标交给已认证的隧道，并用聚合和填充改变写入形态。源码采用 MIT 许可，目前按提交快照分发，尚无正式 Release。

内核介绍

以下章节展开解释各项能力的实际机制；快速事实总览见上方「内核能力」矩阵。

从 SOCKS5 到远端目标

客户端命令 nakis client -c client.json 在本地监听 SOCKS5，默认地址为 127.0.0.1:1080；服务端根据请求中的目标主机和端口建立出口连接。需要代理的应用先接入这个 SOCKS5 地址。参考程序没有图形界面和系统 VPN 接管，Android 的 VPN 界面由 SakuraBox 等下游另行实现。默认 SOCKS5 不要求本地认证，将监听地址改成所有网卡会改变可访问范围。

复用一个隧道怎样减少握手

一条隧道同一时刻承载一个业务会话。当前会话结束时双方发送 NAP，清理状态后可把连接放回池中，下一个目标再复用它；多个并行业务需要多条隧道。预热池提前建立连接，竞速机制在候选连接中选择可用者，能减少等待建立连接的机会，但效果取决于链路和池配置，不能由此推导固定延迟或吞吐提升。

DATA、PAD 与写入聚合

线上帧以两字节大端长度开头：1 至 65534 表示 DATA，0 表示 NAP，65535 后再携带 PAD 长度和填充内容。接收方丢弃 PAD 并把 DATA 交回业务连接。聚合器可把多次小写入合并，填充则增加无业务含义的字节；这些行为涉及带宽、等待和外部可见记录长度的取舍，TLS 加密不会自动隐藏包长和时序。

查看来源

认证、时间窗口与 TLS 绑定

认证消息包含时间戳、16 字节 nonce 和 HMAC-SHA256；服务端以共享 UUID 检查证明、约三十秒时间窗口和 nonce 重放缓存。TLS 隧道还把证明绑定到当前连接的 exporter。参考服务端最低 TLS 1.3，客户端普通 TLS 配置最低 1.2、启用 ECH 时最低 1.3。双方仍需按各自配置完成证书或 pin 校验，不能把共享 UUID 当成服务器证书。

查看来源

证书 pin、ECH 与明文模式

未配置 pin 时，客户端使用标准证书链和服务器名称校验；配置 tls_pins 后，以叶证书 SPKI 的 SHA-256 摘要匹配取代标准链、名称及有效期校验，需要可靠地分发并更新 pin。ECH 使用显式提供的配置，不能把服务端拒绝后的新配置视为已自动采纳。参考实现还允许关闭 TLS，此时只有认证而没有载荷机密性或可靠的服务器身份认证，不能作为加密隧道使用。

查看来源

UDP 的独立隧道模式

UDP 请求使用保留目标 udp.nakis.arpa 协商隧道模式，再按协议封装目标与数据报。它在 TCP 隧道内承载 UDP 数据，沿用底层可靠字节流的传输特性。服务端和客户端都需要理解这项扩展；旧版本服务端的拒绝行为不能通过更换客户端标签消除。

查看来源

公开的 NAP 记录特征

同一作者的 nakis-killer 用 TLS 记录长度分析 NAP：公开样本中，六条已使用 Nakis 隧道全部出现被脚本标记的、线上总长为 24 字节的短记录；二十条未使用预热连接和六条 HTTP/1.1 对照连接没有命中。当前参考源码的 Nap 仍写入两个零字节。样本展示一种可研究的特征，不足以给出普遍识别率、误报率或实际审查部署结论；给 NAP 动态填充是仓库提出的建议。

查看来源

构建、适配与 Android 入口

go.mod 声明 Go 1.24，Makefile 提供 Linux amd64/arm64、macOS arm64 和 Windows amd64 源码构建目标。sing-nakis 是同作者面向 sing 的独立库，要求标准 TLS 栈；SakuraBox v1.0.3-beta.2 则发布了 Android Nakis 支持，其构建文档和源码显示自带适配。三者分别维护，不能由 README 互链推断共享实现或上游 sing-box 已合入。
