Xray-core

开源代理内核 · 亦称 Xray

Xray-core 是从 v2fly-core 特定提交分叉后独立演进的 Go 代理核心，围绕 VLESS、XTLS、REALITY 与 XHTTP 组织传输、安全、路由和透明接管。它适合需要 Project X 协议实现或细粒度入站/出站编排的部署；图形客户端是否开放这些字段必须另行核对。

发展历程

沿革时间线只展示与当前内核关联、并有独立来源的事件；项目的版本发行记录另见下方「版本与发行节奏」。

  1. 2020 年 11 月 9 日

    Xray-core 从 v2ray-core 分叉 →

    Xray-core 建立公开仓库，其项目说明确认 v1.0.0 从 v2fly-core 的特定提交分叉。此后项目围绕 VLESS、XTLS、REALITY 等能力长期独立演进。

    GitHub：Xray-core 初始提交
  2. 2024 年 3 月 27 日

    Xray-core 引入基于后量子密码学的 VLESS Encryption →

    Xray-core 合入代码，基于抗量子密码学标准 ML-KEM-768（Kyber）实现 VLESS 协议的端到端加解密拓展（VLESS Encryption），以抵御“先窃听、后量子破译”的前向安全威胁。

    GitHub：Xray-core Pull Request #3534
  3. 2024 年 6 月 18 日

    Project X 推出自研 XHTTP 传输协议 →

    Project X 团队正式推出专为现代代理设计的 XHTTP 传输协议，基于 HTTP/2 与 HTTP/3 的分块与流控机制优化代理数据封装，显著增强了应对中间人阻断和 CDN 分发的穿透弹性。

    GitHub：Project X 官方讨论 #4113

内核介绍

以下章节展开解释各项能力的实际机制；快速事实总览见上方「内核能力」矩阵。

协议、传输和安全层分开组合

Xray 的配置把 inbound、outbound、streamSettings、security 和 routing 分开。VLESS 或 VMess 只描述代理会话，TCP、WebSocket、gRPC、HTTP/2、XHTTP 等传输再由 streamSettings 选择；TLS、XTLS/ Vision 与 REALITY 负责外层握手和数据路径。因而一个 vless:// 分享链接只能表达部分组合，不能替代服务端完整配置。

查看来源

路由先匹配条件，再选择出站

routing.rules 可以按域名、IP、端口、网络类型、协议嗅探结果、用户或入站标签把连接送到指定 outboundTag；balancer 还可以在多个出站间按策略选择。DNS、FakeDNS 和路由是相互关联但独立的配置面，命中一个域名规则不代表 DNS 查询本身必然经过同一出站。

查看来源

透明接管依赖平台组件

dokodemo-door、tproxy、tun 与 redirect 等入口把系统或局域网流量交给 Xray；实际覆盖范围还取决于系统路由、Wintun 或 Linux 防火墙规则。官方发行包可包含 Windows Wintun，但这不等于所有客户端都启用了 TUN，也不等于服务端具备透明接管。

v26.11.9 的可见变化

本轮固定正式版为 v26.11.9。发行说明提到 XDRIVE 传输的 Google Drive 后端优化，并记录 Chrome 155+ 指纹默认行为的项目说明；这些是该版本的发行上下文，不代表所有下游应用都已同步或所有指纹都适合每条链路。

核心与客户端、面板分工

Xray-core 仓库同时列出官方 Docker、安装脚本、示例和大量 GUI/面板项目，但这些项目拥有自己的版本、配置封装和许可证。使用 v2rayN、Hiddify、3X-UI 或其他界面时，应分别确认它实际携带的 Xray 构建与可编辑字段。
