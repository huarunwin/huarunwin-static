meow-rs

开源代理内核 · 亦称 meow-rs / Meow 内核

meow-rs 是 Max Lv 维护的 Rust Mihomo 兼容内核，面向 meow 系列客户端。它保留 Clash/Mihomo 的规则、订阅和代理组模型，同时增加 dialer-proxy 链路诊断、持久化 logbook、REST API 和 TUN/TProxy 透明接管；README 明确它是 client-only 内核，不提供服务端功能。

内核介绍

以下章节展开解释各项能力的实际机制；快速事实总览见上方「内核能力」矩阵。

兼容 Mihomo 规则，但不是 Go Mihomo 的构建

meow-rs 以 Rust 重新实现 Mihomo/Clash Meta 的 YAML 规则、proxy-provider、rule-provider 和策略组概念；README 同时列出自己的协议适配、API 和数据库目录。应用可以复用部分订阅与规则资料，但字段是否可用仍以 meow-rs 固定版本为准。

查看来源

dialer-proxy 解决的是链路可达性

dialer-proxy 让一个节点通过另一个代理或策略组建立自己的上游连接。meow-rs 会在健康检查通过但链路目标不可达时重新探测链路，并记录实际承载跳数；UDP 只有在前置代理能够中继时才沿链路传递，不能为了维持链路而绕过代理直连。

查看来源

DNS、TUN 与系统流量接管

固定版本提供 DNS 服务器、DNS snooping、Fake-IP 配置和基于 TUN/平台防火墙的透明代理。Windows TUN 依赖 Wintun 与提升权限，Linux/macOS 分别使用 nftables 或 pf；这些条件决定系统流量是否真正进入规则引擎。

查看来源

v0.29.0 的连接回收与流量账本

v0.29.0 增加入站 TCP keepalive 与可选 tcp-idle-timeout，用于回收无 FIN/RST 的僵尸连接；同时增加按日期、主机、应用、策略和接口标签保存 62 天的流量账本。tcp-idle-timeout 默认关闭，不能把该功能写成升级后必然改变已有连接行为。

查看来源

客户端边界与交付

meow-rs README 列出 Android、iOS、iPadOS 和 Apple TV 的 meow 应用，并明确核心是 client-only；服务端、面板和发行包由不同项目负责。MIT 许可证只覆盖该仓库，不能替下游应用或内置的其他组件作许可证结论。
