dae

开源代理内核 · 亦称 daeuniverse/dae / dae 内核

dae 是 Linux eBPF 高性能透明代理：它把连接捕获、直连旁路和流量分流尽可能放进内核路径，只有需要代理的流量进入用户态转发。它适合 Linux 主机、网关和路由器，不是跨平台 GUI 核心，也不等于 v2rayA 的当前内核。

内核介绍

以下章节展开解释各项能力的实际机制；快速事实总览见上方「内核能力」矩阵。

eBPF 数据路径与 Real Direct

dae 使用 eBPF 在 Linux 内核侧完成透明接管和规则判断；命中 must_direct 的流量可以直接通过，而需要代理的连接才进入用户态代理出口。这是减少直连转发开销的路径设计，不应扩写成对所有代理流量都有固定性能提升。

查看来源

规则按来源、进程和网络条件组合

dae 支持按本机进程名、局域网 MAC、协议、端口、DNS 和反向解析结果组织规则，并可用 invert match。路由动作可以选择策略组、直连或拒绝；VPS 作为网关时还要为服务端监听端口显式写 must_direct，避免 UDP 回包再次被代理。

查看来源

自动节点选择与 DNS

策略可以分别测量 TCP/UDP、IPv4/IPv6 延迟并选择节点；DNS 组件提供上游、规则和缓存控制。节点选择、DNS 路由与 eBPF 捕获是不同层，调试时需要分别确认规则命中、解析路径和实际出站。

v2.1.1 的数据面重构

v2.1.1 发布说明记录 kdae full sync 数据面/控制面重构、修复组覆盖下的 DNS 保留、修复 wan_egress pass-through 行为，并更新内置 outbound fork。升级时应对照 example.dae 和新手文档检查已有规则。

Linux 运行条件与项目边界

dae 需要兼容的 Linux 内核、eBPF/CO-RE、网络管理权限和相应防火墙/路由设置；daed 是独立网页面板，v2rayA 只是项目 README 提到的前身。核心、面板和使用它的 GUI 应用各自有独立版本与许可。
