V2Ray 创世作者：开启模块化多协议代理与 Web 伪装时代的先驱

在风暴与断层中孤身奠基 Project V，以 Inbound/Outbound 解耦架构与 VMess 协议重塑中文网络抗审查版图

第一幕 · 破晓：至暗时刻的孤勇应战

2015 年 8 月中旬，中文互联网抗审查领域遭遇了前所未有的剧烈震荡。

8 月 17 日，Shadowsocks 原作者 clowwindy 留下一句“Two days ago, the police came to me...”后被迫删除主仓库并退出维护；数日之后，长期为数以百万计网民提供免费代理的 GoAgent 亦遭到整肃，作者 phuslu 清空了全部项目代码。

两面旗帜的轰然倒下，在整个开源技术社区与千万用户心头投下了沉重的绝望阴影，外界一度断言民间的网络穿透技术已走入历史终局。

就在这片万马齐喑的寒冬与断层之中，2015 年 9 月 5 日，一位在 GitHub 上署名 Victoria Raymond 的开发者以一次名为“init”的代码提交（Commit 4c03bf0d），悄然创建了名为 v2ray-core 的全新代码仓库。

在项目最初的 README.md 中，Victoria Raymond 没有长篇累牍的理论说教，而是用一段极其平实、却充满磅礴力量的技术人宣言打破了死寂：

「我是只是一名普通的开发人员，已肉翻，本已不依赖这些翻墙工具，但 ShadowSock 和 GoAgent 被迫删除代码的事件实在太恶心，不得不做点什么了。」

她将项目命名为 Project V，并在设计文档中坦言，“V2”来源于划时代的 V-2 火箭，Ray 即射线，寓意着穿透封锁铁幕的新一代利刃。

她以纯粹的技术执念接过了火种，凭一己之力拉开了抗审查网络“第二世代”的历史大幕。[1][2]

第二幕 · 奠基：积木化解耦哲学与 VMess 协议

在 V2Ray 诞生之前，主流代理工具无论底层算法如何更迭，其整体架构大多停留在“特定端口监听至特定加密转发至远端解密”的点对点单隧道模型。

这种硬编码设计一旦遭遇协议特征被识别或端口被封锁，整套链路便彻底瘫痪，用户与开发者不得不重新编写新的客户端与服务端程序。

Victoria Raymond 在 2015 年 9 月的《V2Ray 设计概要》（spec/design.md）中，破天荒地提出了解耦的模块化工具包思想：

「V2Ray 为模块化设计，模块之间互相独立。每个模块可单独使用，也可和其它模块搭配使用。」

她将网络代理拆解为三大核心正交维度：负责接收外部流量的入站网关（Inbound）、负责根据域名与 IP 判定走向的路由引擎（Router），以及负责向目标网络转发数据的出站网关（Outbound）。

这种将复杂网络管道化、乐高积木化的工业级架构，不仅赋予了代理核心无与伦比的扩展性，更在此后十年中成为 V2Fly、Xray 以及 sing-box 等无数现代核心的通用架构范式。

与此同时，为了从数学与协议层彻底根除简单对称加密容易被主动探测（Active Probing）识别的弊端，Victoria Raymond 亲手设计并推出了 V2Ray 原生通信协议——VMess。

VMess 抛弃了预共享密码直接派生密钥的旧式做法，采用全局唯一的用户 ID（UUID）结合 16 字节时间戳（UTC 时间误差限制在 120 秒以内）生成认证哈希头，从根源上粉碎了审查系统通过重放攻击诱骗服务器响应的可能；随后引入对称加密（AES-128-GCM 与 ChaCha20-Poly1305）保护真实载荷。

2016 年初，她更独创了“动态端口（Dynamic Port）”跃迁机制（Commit 98d99a1f），使服务端能够随机变换通信端口，让审查者的单端口封锁策略彻底失效。[3][4][5][6]

第三幕 · 拟态：Web 伪装革命与融入公网主流

伴随着机器学习与深度包检测（DPI）技术的飞速演进，防火长城对“非标准加密流量”的识别精度与日俱增。

任何在网络链路上表现出高熵值、无特定应用层协议特征的 TCP 流量，都会被列入可疑名单并遭受限速或丢包阻断。

面对严峻的审查威胁，Victoria Raymond 再次做出了改变整个行业技术走向的开创性决断：放弃与审查算法无休止地进行加密特征修补，转而将翻墙流量彻底“藏入”最常见、最合规的公网 Web 流量之中。

她在 V2Ray 中率先实现了传输层协议与代理业务的彻底分离，开创性地将标准 WebSocket 协议与 TLS 加密通道作为底层载荷承载 VMess 数据（PR #238，Commit 667b71aa）。

由于 WebSocket 握手完全遵循标准 HTTP/1.1 与 HTTPS 规范，审查者面对的是完全合法的 Web 握手与标准的 TLS 证书协商。

更有甚者，这种流量能够毫无阻碍地穿透 Nginx、Caddy 等主流反向代理，甚至能够直接挂载在 Cloudflare 等公有 CDN 后面，通过 CDN 的全球节点实现“任播中转与真实 IP 隐匿”。

随后，她又于 2018 年 3 月推进实现了基于标准 HTTP/2 协议的多路复用传输（Commit d207d953），进一步逼真拟态现代浏览器的访问特征。

这一系列创举标志着翻墙攻防正式进入了“借壳伪装”与“流量拟态”的新时代，彻底改写了攻防博弈的战略平衡。[8][11]

第四幕 · 攻坚：mKCP 弱网抗丢包与传输层革命

在解决流量隐蔽性的同时，跨国公网链路日益严峻的丢包与 TCP 拥塞控制劣化，成为了悬在无数用户头顶的另一道难题。

高丢包环境下，传统 TCP 拥塞控制算法会剧烈收缩滑动窗口并频繁超时重传，导致网络连接严重降速，高清流媒体与实时交互几乎无法维系。

面对这一痛点，Victoria Raymond 带领团队在 V2Ray 中自研并深度集成了基于 UDP 的 mKCP 传输协议（PR #170，Commit 22ce652a）。

通过对经典 KCP 算法的深入定制，优化了握手校验、流控窗口与自适应纠错填充（Padding），以适度增加冗余带宽的代价换取了极致的低延迟与高容错能力。

这使得处于弱网与恶劣跨境链路下的用户依然能获得平稳的高吞吐体验，攻克了长久以来跨国大文件传输与视频推流的卡顿瓶颈。

更为关键的是，Project V 的分层设计让传输层与上层协议完全正交解耦：同一个 VMess 协议可以在 TCP、mKCP、WebSocket、HTTP/2 上自由切换组合。

这种将传输管道彻底参数化、可插拔化的工程成就，为抗审查软件树立了全新的技术标杆。[7][10]

第五幕 · 繁盛：克制的分工与图形客户端生态繁荣

从 2015 年秋天到 2018 年底，Victoria Raymond 主导并推动 V2Ray 经历了四个宏大的主版本迭代（v1.0 至 v4.0）。

在这四年间，V2Ray 从一个初生的小型原型，演进为一个包含完整配置规范、多平台交叉编译流水线、ProtoBuf 接口与高并发 Go 代码的工业级网络核心。

在项目规模迅速膨胀的浪潮中，Victoria Raymond 始终坚守着极其罕见的极客克制：她明确将精力聚焦于核心守护进程与协议实现，主动不涉足单一操作系统的图形界面，而是毫无保留地开放 API 与标准化配置接口，甘为底层基石。

这种克制与远见，直接孵化并催生了后续繁荣的客户端生态。

开发者 2dust 基于 V2Ray 核心先后开发出 Windows 平台的 v2rayN 与 Android 平台的 v2rayNG；yanue 打造了 macOS 平台的 V2rayU；社区开发者们亦推出了 Linux 下基于 Web 的 v2rayA。

一系列优秀的图形客户端如雨后春笋般竞相涌现，让昔日晦涩复杂的命令行配置飞入寻常百姓家，使数以千万计的普通用户能够一键跨越信息高墙。[9][12]

第六幕 · 远去：全自动托管交接与长青的代码血脉

2019 年 2 月 28 日，在向项目合并了第 1581 号 Pull Request（Commit 1dab33b0）、更新了官方发布的 GPG 签名公钥（Commit 8f6637b8）以及构建流水线配置（Commit d21d02d0）之后，Victoria Raymond 彻底完成了项目全自动托管与构建闭环改造。

没有告别演说，没有功劳簿宣讲，她在完成最后一次自动化交接后，悄然退出了全部公开代码仓库与社交网络，如风一般归于平淡。

为了不让千万依赖 V2Ray 的网民再次陷入停更恐慌，社区核心成员（Kslr、Shelikhoo、liberal-boy）迅速接力，于 2019 年春正式组建了 V2Fly 社区，完全承接起内核的维护、规范化发布与漏洞修复使命。

Victoria Raymond 虽然远去，但她亲手开创的设计哲学与工程血脉却长青不衰：

2020 年，开发者 RPRX 基于 v2ray-core 深度重构，孕育出了支持 XTLS 零拷贝黑科技的 Xray；nekohasekai 在设计 sing-box 时，亦深度承袭了 Project V 积木化分流与多协议抽象的核心思想。

作为中文抗审查网络从废墟走向现代工业化体系的筑基之人，Victoria Raymond 以代码为笔、以匿名守护自由，在人类追求网络自由的丰碑上刻下了无可替代的名字。[13][14][15][16][17]

代表作品与核心贡献

V2Ray (Project V)

访问作品

具有划时代意义的模块化代理内核平台，首创 Inbound/Outbound 解耦与路由引擎分流体系

VMess 协议

访问作品

V2Ray 原生安全代理协议，基于 16 字节时间戳鉴权与对称载荷加密，开启防重放与动态端口跃迁先河

Web 流量伪装范式 (WebSocket + TLS / HTTP/2)

首次将翻墙数据伪装为合规 Web 流量并借力反向代理与 CDN 转发，奠定现代抗审查拟态伪装基石

mKCP 传输协议

基于 UDP 的低延迟抗丢包优化传输层实现，在恶劣跨国网络环境下保障通信吞吐与抗干扰能力

致敬开发者的坚守

代码或许归档，但火种永不熄灭。为推动网络对抗演进与底层工程突破的开拓者献上一份敬意。

编年大事记

2015-09-05

V2Ray 创世提交：Project V 与 VMess 破土动工

在 Shadowsocks 与 GoAgent 相继遭外力停更的至暗时刻，Victoria Raymond 提交了 v2ray-core 的初始代码（Commit 4c03bf0d），宣布 Project V 诞生并确立模块化工具包设计与 VMess 协议雏形。[1][2]

2015-11-29

V2Ray 1.0 正式发布：完成首个可独立运行版本

按照初版路线图，V2Ray 1.0 正式打标发布（Tag v1.0），实现了单服务器模式、TCP 传输与基于 VMess 协议的端到端基础代理功能。[9]

2016-01-22

实现动态端口分配（Dynamic Port）机制

提交 dynamic allocation of inbounds 架构（Commit 98d99a1f），开创服务端端口动态随机跃迁先河，有效破解审查系统对固定服务端口的精准阻断。[6]

2016-06-13

集成 mKCP 传输协议：解决恶劣链路高丢包痛点

针对跨国骨干网恶劣丢包与高延迟环境，合并 PR #170（Commit 22ce652a），引入基于 UDP 的 mKCP 传输层与自适应重传，显著提升弱网吞吐。[7]

2016-08-15

首创 WebSocket 与 TLS 伪装：开启 Web 流量借壳范式

合并 PR #238（Commit 667b71aa），V2Ray 正式支持 WebSocket 传输与 TLS 加密包装，率先实现了翻墙流量伪装为标准合规 Web 流量并支持反向代理与 CDN 转发的技术范式。[8]

2016-08-20

V2Ray 2.0 发布：“One year” 一周年里程碑

在项目成立一周年之际正式发布 2.0 版本（Tag v2.0），全面支持多服务器模式、mKCP 与 WebSocket 传输通道，奠定多传输抽象架构基石。[10]

2018-03-01

实装 HTTP/2 (h2) 传输协议

提交 h2 transport（Commit d207d953），实现基于标准 HTTP/2 协议的多路复用网络传输，进一步丰富了 Web 拟态伪装的技术武器库。[11]

2018-11-01

V2Ray 4.0 发布：架构进入成熟工业级阶段

V2Ray 4.0 正式发布（Tag v4.0），全面重构入站出站流水线、多用户配额与高级路由规则体系，项目基础设施自动化与跨平台发布能力趋于完善。[12]

2019-02-28

完成自动化构建与签名公钥更新，正式交接隐退

Victoria Raymond 合并第 1581 号 PR（Commit 1dab33b0），更新官方发布签名公钥（Commit 8f6637b8）与构建脚本（Commit d21d02d0），完成项目全自动托管后平静淡出公众视野。[13][14][15]

2019-04-15

V2Fly 社区成立接力掌舵

为确保 V2Ray 核心的长期维护与生态平稳过渡，社区核心维护者组建 V2Fly 组织接续掌舵，将 V2Ray 精神与代码血脉继续发扬光大。[16][17]
