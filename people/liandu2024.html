软路由的一键集成者：Open-Box 与极简 sing-box Web 体验

用安装脚本与 Web 面板整合 sing-box 部署，自有程序按专有许可分发

时代与嵌入式软路由代理配置繁杂割裂的困境

软路由通常承载着全屋家庭或小型机构的流量分流中枢，但传统插件往往需要用户手动安装多个依赖包、配置复杂的 iptables/nftables 防火墙链路并手写 JSON 配置文件。

任何一个软件包版本脱节或配置格式笔误，都可能导致整网断网或路由器死机假死，将数以万计缺乏 Linux 底层网络知识的普通用户拒之门外。[1][2]

安装脚本与 Web 管理面板

liandu2024 秉持“化繁为简、打开即用”的产品理念，为 OpenWrt 量身打造了一体化安装闭环。通过一行 Shell 脚本即可自动拉取适合目标硬件架构的 sing-box 编译产物并初始化服务。

项目提供浏览器内的 Web 管理面板。官方版权说明确认其前端以 AnGe-ClashBoard / zashboard 为基础，zashboard 原始代码保留 MIT 许可，不能把这部分上游许可概括为整个 Open-Box 的许可。[1][3][8]

硬核工程深水区：sing-box 补丁适配、SmartDNS 集成与自愈机制

在工程底层，作者针对 sing-box 在 OpenWrt 嵌入式平台上的 DNS 劫持与 TCP 分流缺陷研发了专属修复补丁，并深度整合了 SmartDNS 的并发解析机制。

在 2026 年 8 月至 9 月高频发布的逾百个小版本迭代中，作者持续完善了流程式节点测试、配置备份回滚与内核异常自愈重启逻辑，极大地保障了 7x24 小时无人值守时的网络鲁棒性。[4][5]

当前公开范围与许可边界

官方在 2026-10-13 的提交中加入专有许可证与版权范围说明，声明自有材料从 v0.1.321 起按闭源专有软件分发。当前公开的部署脚本和 Docker 文件用于安装、封装发行包，不能据此认定完整产品源码已公开。

sing-box 内核继续保留 GPL 许可，官方 Release 提供内核源码附件；zashboard 原始代码继续保留 MIT 许可。专有声明不追溯撤销旧版本或其他材料已经授予的开源许可，本页不据此作版权责任或许可证合规结论。[6][7][8][9]

liandu2024：Open-Box Windows 严格 DNS 接管与 NRPT 兼容问题仍待修复

liandu2024 在 Open-Box #549 中说明，Windows 的 NRPT 会把私有域查询发往指定 DNS，而 nslookup 的 TUN DNS 是另一条路径；直接访问目标地址可达，但指定 DNS 的 UDP/TCP 53 超时。当前配置固定启用 strict_route，项目尚未为 NRPT 指定解析器保留例外，排查已收敛到严格 DNS 接管兼容路径；Windows WFP 命中和修复回归尚未完成，v0.1.355/v0.1.356 未宣称修复。

liandu2024：Open-Box 升级改为下载完成后再停内核

liandu2024 在 Open-Box #720 中说明，旧升级入口在下载前先停内核，系统网络随后无法连接镜像/GitHub；当前脚本改为在原网络环境下载并校验，完成后才替换服务。v0.1.355 含该修正，但旧版已安装的启动脚本需先更新一次；建议先确认内核恢复，再用保留现有网络及分流的 --direct 下载并校验脚本后升级，失败时不要继续停内核。

liandu2024 说明 Open-Box 故转不会自动升回更靠前的备用

liandu2024 在 Open-Box #714 中说明，351/352 的故转主用仍指第一个页签，自动恢复目标也仍是主用；当前备用健康时，没有恢复到更靠前备用的分支。第一条没有有效成员与备用 1 恢复后仍停在备用 2 需要分别处理，前者显示 backup 不能当作主用已恢复，后者须单独复现和回归。作者明确 0.1.352 未修改这条决策，不能用 #668 的主用检测修复覆盖此问题；暂沿用用户验证过的移走空首项或调整顺序的规避，议题保持打开。
