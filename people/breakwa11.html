ShadowsocksR 创世作者：协议混淆革新与节点订阅生态的奠基人

开创协议混淆（Obfs）与插件分层架构，发明 ssr:// 订阅格式，深刻重塑翻墙生态与机场分发范式

第一幕 · 裂变：后 Shadowsocks 时代的断层与风暴中的接棒者

2015 年 8 月，伴随着 Shadowsocks 原作者 clowwindy 遭受重压被迫清空源码仓库，中文互联网抗审查生态陷入前所未有的剧烈震荡。

雪上加霜的是，审查系统的深度包检测（DPI）与主动探测（Active Probing）能力正经历质的跃升：原生 Shadowsocks 的纯对称加密流虽然隐蔽，但在骨干网统计学分析与高熵特征识别面前逐渐出现被动识别与 QoS 严重降速的隐患。

在主流社区群龙无首、海外 VPS 节点频繁遭遇阻断的迷茫时刻，开发者 BreakWa11（破娃酱）在 GitHub 上建立了 ShadowsocksR 分支。

2015 年 9 月 11 日，BreakWa11 向仓库提交了具有里程碑意义的“add obfs plugin”代码变更（Commit a723c2f0），正式拉开了 ShadowsocksR 独立技术路线的大幕。[1][6]

第二幕 · 构架：协议鉴权与流量混淆的正交双层革命

BreakWa11 敏锐洞察到：单纯依靠对称加密无法抵御审查系统对“无特征流量（High-entropy traffic）”的统计封锁，必须在加密层之外引入针对握手鉴权的“协议（Protocol）”与针对流量外观的“混淆（Obfs）”双层解耦机制。

在 Protocol 协议层，先后研发 auth_sha1_v4、auth_aes128_md5 及 auth_chain_a/b 等鉴权协议，在连接建立之初加入时间戳校验、随机盐与数据包长度混淆，从根源上摧毁了审查设备构造非法重放探测包的主动探测漏洞。

在 Obfs 混淆层，设计 http_simple、tls1.2_ticket_auth 等混淆插件，将翻墙流量精细伪装成常规 HTTP 请求头或标准 TLS 1.2 握手 Client Hello，借助 SNI 拟态在防火墙眼里“借道通行”。[2][6]

第三幕 · 质变：发明 ssr:// 链接与批量订阅——重构整个生态的分发范式

面对多节点手动配置繁琐、参数极其复杂的终端痛点，BreakWa11 于 2016 年 6 月在 ShadowsocksR-C# 3.8.3 beta 中首次实装了以 ssr:// 为前缀的 Base64 节点 URI 格式（Commit 4e263bec）。

2017 年 6 月 3 日，BreakWa11 提交了划时代的 add subscribe 变更（Commit 0eb2b9c7），首次发明了基于 HTTP(S) API 接口拉取的批量节点订阅（Node Subscription）机制。

用户只需在客户端中粘贴一个订阅 URL，即可一键自动同步拉取数十乃至上百个节点的 IP、端口、协议与混淆参数。

这一原本为了方便公益节点分发的工程创新，在客观上彻底引爆并奠定了后来“机场（Airport）”商业化集中分发的产业雏形，至今仍是整个翻墙生态不可撼动的通用标准。[3][4][7]

第四幕 · 激辩：GPL 开源争端与“真伪伪装”的哲学交锋

伴随着 SSR 影响力的指数级扩张，激烈的社区伦理与开源合规争端也接踵而至。

SSR 早期发布 Windows 二进制编译包时未及时公开完整的 C# 客户端源码，引发了开源社区关于违反 GNU GPL 许可证的严重质疑与舆论风波；面对指责，BreakWa11 随后补齐并开放了全部客户端源码，将项目许可证调整为多重自由软件许可。

在技术路线上，围绕流量混淆的争论更为激烈：原版社区坚持端到端强加密配合轻量可插拔 SIP003 插件路线，批评“伪装 TLS（Mocking TLS）”缺乏真实证书链校验，属于虚假的安全幻觉；而 SSR 支持者则以立竿见影的低阻断率和抗 QoS 限速实绩进行辩护。

2017 年 7 月 24 日，面对外界针对协议特征的质疑，BreakWa11 在 GitHub 发布了闭源的“SS被动检测程序”（Issue #868），试图证明原版协议的特征漏洞，这一举动瞬间将开源阵营的技术论战推向了最高潮。[7][9]

第五幕 · 陨落：恶性人肉风暴与悲壮决绝的删库退隐

2017 年 7 月 27 日，开源社区的技术争议骤然演变为残酷的网络暴力危机。

恶俗网络群体对 BreakWa11 发起了恶性人肉搜索（Doxxing），公开了所谓的个人信息并对其发出恶毒的人身攻击与极端威胁，波及无辜人员。

面对无辜第三方被牵连伤害的现实风险，BreakWa11 在当天下午做出了痛苦而坚决的决定：在向仓库提交了 3.4.0 版本的最后一次修改（Commit fd723a92）后，毅然清空并删除了 GitHub 下所有相关代码仓库，解散全部交流社群。

她在社交平台上留下最后声明，澄清被公开的身份并非其本人而是随意填写的无关第三方，为了不再让无辜人员承受骚扰，她决定彻底退出开源维护，永久告别中文网络。这是中文开源抗审查历史上最沉痛的悲剧时刻，敲响了保护开发者线下安全与隐私的最高警钟。[5][8]

第六幕 · 遗产：从灰烬中重生的星火与抗审查史上的不朽印记

BreakWa11 退隐后，社区分支 ShadowsocksRR（SSRR）接力接手代码维稳与客户端适配，承接并延续其开源遗产。

更深远的是，BreakWa11 所确立的节点批量订阅范式、防主动探测思路与流量混淆哲学，彻底融入了后世翻墙工具的基因骨髓：V2Ray、Clash、sing-box、Shadowrocket 等现代核心与客户端无一不在深度享用她留下的订阅生态与拟态思想。

她在中文互联网最狂暴的逆风中走过，留下了毁誉交织的争鸣，但更留下了一套让千万人得以看见世界的代码与标准。在数字围墙与人类自由的抗争史册中，BreakWa11 的名字注定是一座无法被绕过的石碑。[6][7]

访问作品

批量节点订阅格式 (SSR Subscription)

访问作品

编年大事记

2015-09-11

提交 add obfs plugin 开启混淆探索

BreakWa11 在 Shadowsocks 分支中提交 add obfs plugin 变更（Commit a723c2f0），首次引入混淆插件机制，拉开 ShadowsocksR 独立技术演进路线的大幕。[1]

2015-12-14

实现 tls1.0_session_auth 与 auth_sha1

向内核引入初始 TLS Session 会话混淆与 SHA1 握手鉴权插件（Commit aff97d4c），开启协议层防主动探测与流量外观伪装。[6]

2016-04-17

发布 tls1.2_ticket_auth 模拟现代 TLS 握手

提交 tls1.2_ticket_auth 插件（Commit 95bc6e4a），支持基于 Session Ticket 的 TLS 1.2 Client Hello 拟态混淆，显著降低骨干网被动识别概率。[2]

2016-06-28

发明 ssr:// 标准节点 URI 方案

在 ShadowsocksR-C# 3.8.3 beta（Commit 4e263bec）中首次实装 ssr:// Base64 编码节点链接，统一多参数节点分享语法。[3]

2017-06-03

首创 HTTP(S) 批量节点订阅机制

在 ShadowsocksR-C# 提交 add subscribe（Commit 0eb2b9c7），首次发明通过 URL 批量自动同步多节点配置的订阅架构，直接催生现代“机场”产业范式。[4]

2017-07-24

发布 SS 被动检测程序引发社区论战

在 GitHub 仓库发布 SS 被动检测程序（Issue #868），就流量指纹识别与协议安全性展开公开辩析，引发社区广泛争鸣。[9]

2017-07-27

发布 3.4.0 版本并因恶性网络骚扰宣布退隐

提交 3.4.0 版本（Commit fd723a92）后，遭遇恶性人肉搜索与威胁；为保护无辜受牵连人员，BreakWa11 删除了 GitHub 上的全部项目代码并宣布停止维护。[5][8]

2017-07-29

社区分支 ShadowsocksRR 接棒维护

社区开发者组建 ShadowsocksRR 组织接手代码维稳与客户端适配，承接并延续 SSR 开源遗产。[6]
