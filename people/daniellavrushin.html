DanielLavrushin：B4 可能把 TLS 选择解析成同域 QUIC 伪装

DanielLavrushin 说明，B4 Discovery 只让用户选择 TLS capture，却按域名映射 capture；同域同时存在 TLS 与 QUIC 时，映射顺序可能让 QUIC 内容作为 TCP fake 发出。其探针在 400 次查找中得到 QUIC 360 次、TLS 40 次，建议仅在 loadCustomPayloads 中保留 TLS capture 并补充双协议测试。

2026.11.06 16:05:03（UTC+8）来源：GitHub

DanielLavrushin：B4 Discovery 卡片与 Apply 对话框的主机勾选状态不一致

DanielLavrushin 说明，B4 Discovery 结果卡会把已由其他 set 处理的主机显示为已勾选，但 Apply 对话框会按实际匹配将其取消勾选并提示归属，用户直接创建 set 可能遗漏卡片显示的主机。问题可由卡片复用 checkDomain 结果修正；作者称该现象在 1.90.0 前主分支 smoke test 中发现。

2026.11.06 16:05:02（UTC+8）来源：GitHub

DanielLavrushin：ClientHello 分段时 B4 可能漏计重传，导致停滞升级不触发

DanielLavrushin 说明，ClientHello 的域名位于第二个 TCP segment 时，内核重传的首段没有域名，B4 的 stall escalation 和 IP Block Detection resend check 因而仍只计一次，连接可能等待客户端超时；在其测试中，域名位于第二段的停滞升级为 0/3。建议按序列号识别已解析域名连接的首段重传，并覆盖两类触发器的网络命名空间测试。
