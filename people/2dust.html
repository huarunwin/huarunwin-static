把客户端长期维护下去：用七年坚守筑就千万用户的数字方舟

不喧哗、不结盟、不退缩，以数千次扎实提交将底层协议转化为两端坚如磐石的日用工具

序幕：聚光灯外的隐形战场与被低估的客户端工程学

在开源网络对抗的宏大叙事中，新协议的握手消减、TLS 拟态伪装与抗重放数学算法往往最令极客们心潮澎湃。

然而一个残酷的现实是：在这个世界上，超过 99% 的普通用户永远不可能在终端里手动敲击命令行，更不可能在满屏的花括号与逗号中手写配置数百行的复杂 JSON 路由。

如果没有稳定、容错率极高的图形界面（GUI）作为桥梁，哪怕再精妙绝伦的协议核心，最终也只能沦为少数专家的代码标本。

更艰难的是，图形客户端的开发绝非简单的“画个 UI 壳子”，而是一场与操作系统底层碎片化特性的无休止肉搏：Windows 繁杂的注册表代理回调、系统代理死锁、各大手机厂商对后台进程残酷的省电清理、以及网络断开与 Wi-Fi 切换时的无感自愈——每一个细微的边界情况，都会立刻化作屏幕前普通用户“打不开网页”的焦虑。

正是在这片最容易被挑剔、最缺乏镁光灯注视、维护负担极其沉重的深水区里，开发者 2dust 展现出了超乎寻常的耐力与毅力。[2][3]

破晓：双端创世与千万级装机的日常基准

2019 年 5 月 15 日，2dust 在 GitHub 上推送了 v2rayNG 的首个提交（Commit 29d3fb7，Tag 1.0.0）。紧接着在 5 月 18 日，代码仓库正式向公众开放。

在 Android 平台上，他巧妙封装操作系统底层的 android.net.VpnService，攻坚克难实现了极其精细的分应用代理（Per-App Proxying）机制，并深度适配了国产定制系统的严苛保活策略，使 v2rayNG 迅速成长为移动端出海冲浪的首选利器。

两个月后的 2019 年 7 月 30 日，2dust 在桌面端迎来了关键突破：他在 GitHub 建立了 v2rayN 仓库（Commit 7894dd9），并在数分钟后发布了首个公开版本 2.30（Commit cf6c20b）。

在初版 README 中，他写下了平实克制的定位：“v2rayN 是一个基于 V2Ray 内核的 Windows 客户端，支持多种协议与自定义路由规则。我们尽量保持多核心兼容与轻量化。”

基于稳健的 .NET 技术栈，他打造了一套极其契合国内用户习惯的托盘应用。扫描屏幕二维码添加节点、Ctrl+V 批量导入剪贴板分享链接、真连接延迟（True Ping）测速、自动配置系统代理与 PAC 规则列表——这些在今天被视为行业理所当然的基准功能，皆是在 2dust 一次次细致打磨下成为了中文社区的通用标准。[4][5][3][2]

抉择：阵营风暴下的中立定力与 ECoreType 解耦

伴随着代理技术的发展，社区在 2020 年底经历了剧烈的路线分化：伴随着 Xray-core 的独立分叉，不同技术流派之间时常出现激烈的争论与格式互斥。

面对社区的技术纷争与讨论区的纷杂噪音，2dust 展现出了极其超然的格局与务实态度——坚决恪守“核心中立（Core Neutrality）”路线。

他不参与任何站队，也不在社区争论中消耗精力。2020 年 12 月 25 日圣诞节之夜，2dust 在 Commit c2c9c6a 中提交了里程碑式的代码文件——ECoreType.cs，正式定义了多核心共存枚举：v2fly_core 与 xray_core。

这一轻巧却极具前瞻性的架构重构，将前端界面逻辑与底层运行内核彻底解耦。用户无需在不同的软件客户端之间艰难二选一，只需在同一个熟悉的界面中自由勾选，即可一键切换底层运行引擎。[6][2]

包容：生态罗塞塔石碑与系统级 TUN 虚拟接管

随着协议的爆炸式衍生，中文互联网生态中出现了宛如巴别塔般混乱的节点格式：vmess://、vless://、ss://、trojan://，再加上 Clash 的 YAML 语法与各类 Base64 订阅源，格式碎片化让普通用户苦不堪言。

2dust 在客户端内部编写了极其强韧的容错解析引擎，使 v2rayN 与 v2rayNG 化身为跨越格式鸿沟的“罗塞塔石碑”。无论导入何种格式的订阅，客户端都能自动识别、清洗并精准转换为对应内核的最佳运行姿态。

2022 年 9 月 20 日，2dust 合入了社区 PR #2640，为 v2rayN 带来了对新一代代理核心 sing-box 的原生支持。

紧随其后的 2023 年 1 月 2 日（Commit 9d38d89），他进一步推出了基于 sing-box 的系统级增强 TUN 模式。依托 Wintun 虚拟网卡技术，客户端彻底摆脱了系统 HTTP 代理对非标准应用（如终端命令行、联机游戏、设计工具）的拦截盲区，实现了开箱即用的全局透明接管。[7][2]

涅槃：v2rayN 7.0 跨平台重构与移动端架构演进

在长达五年的迭代中，v2rayN 的代码库一直与 Windows 专属的 WPF 界面框架紧密绑定。如何打破操作系统的藩篱，让 Linux 桌面用户也能享受到同等便捷的图形体验，成为了 2dust 面临的新命题。

2024 年 8 月 29 日，2dust 提交了 Commit 6c9db51（“Creating a new desktop app with avaloniaui”），正式拉开了基于 Avalonia UI 的跨平台重构大幕。

他大刀阔斧地将原本与 Windows 绑定的业务逻辑完全剥离为纯净的跨平台服务核心。2024 年 10 月 24 日，v2rayN 7.0.0 正式发布，首次推出了采用 Avalonia UI 的 Linux x64 版本，彻底补齐了开源操作系统桌面的最后一块拼图。

而在移动战线，2dust 同样步履不停。2026 年 1 月 14 日，v2rayNG 迎来 2.0.0 重磅更新（Commit a3972b9），将核心逻辑彻底重构为现代 Jetpack ViewModel 架构，统一了 V2RayNativeManager 原生调用链，使移动端客户端在现代 Android 系统上的运行稳定性与资源消耗再登新台阶。[8][9]

守夜：七载如初的钟摆与数字方舟的常青基石

在瞬息万变的开源世界里，凭借一时激情发起一个热门项目并不罕见，但能够数年如一日、持续面对数以万计琐碎的 Issue 报错而不退场、不言弃，是一种极度罕见的伟大品格。

2dust 在项目维护指南中曾写下感动无数用户的朴素信条：“只要还有一个人在用，就保持更新。界面可以朴素，但分流与兼容必须扎实可靠。提 Issue 请务必附带系统版本与详细日志，少一点情绪化吐槽，多一份协作。”

从 2019 年夏天的首行代码，到 2026 年秋天依然高频发布的 v2rayN 7.25.4 与 v2rayNG 2.3.10，2dust 的提交记录如同永不停歇的钟摆，整整跳动了逾两千六百个日夜。

他不参与社区的喧闹论战，也从不在聚光灯下彰显光环。但在狂风骤雨掠过数字世界的岁月里，他用超过七年的沉默坚守证明：最坚实的力量，永远来自于日复一日为你修复那一行断网代码的守夜人。[10][3][2]
