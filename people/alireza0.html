双轨并进的协议拓荒：alireza0 的 X-UI 重塑与 S-UI 创世

以单兵之力横跨 Xray 与 sing-box 双轨生态，用直观界面驯服最复杂的现代协议

第一幕 · 破局修补：X-UI 的失控危机与精准锁链

2023 年初，在原版 X-UI 停滞不前的背景下，随着抗审查协议向现实生产环境迁移，一个致命的运维痛点浮出水面：原生面板缺乏对单个账号连接行为的约束能力。

在多用户共享节点场景中，一个账号若在数十台设备间无节制分发，极易触发云服务商的异常流量风控，甚至导致整台服务器 IP 被直接拉黑。更严重的是，多客户端并发争抢带宽常使母机 CPU 长期处于 100% 满载过载状态。

“必须让每个配置都有据可查，让每一次超限都无所遁形。”2023 年 2 月 6 日，alireza0 建立了 alireza0/x-ui。他深入 Xray 底层连接跟踪机制，重构了流量与状态审计模块。

他率先在面板中加入了精确到单用户的 IP 数量并发限制算法与到期时间硬性熔断；同时引入集成化的 Telegram Bot 接口，使运维人员无需守在电脑前，在手机聊天窗口中就能实时收到节点告警并完成远程一键封禁。[1][2]

第二幕 · 风起 sing-box：新内核狂潮下的“控制台真空”

2024 年初，代理生态的风向发生了历史性的转变。随着 nekohasekai 打造的 sing-box 核心异军突起，其基于统一 JSON 抽象的数据结构、精悍的内存占用以及对 TUIC、Hysteria 等前沿 UDP 协议的原生支持，迅速吸引了全球极客的目光。

然而，内核底层的飞跃却让普通服务端运维者陷入了前所未有的痛苦之中。与 Xray 相对直观的配置模板相比，sing-box 采用了深层嵌套的 JSON 规范与严格的路由规则集，手写配置的门槛极高，稍有标点错误便无法启动。

而在当时的服务端生态中，虽然 Xray 拥有成熟的面板群，面向 sing-box 的原生自托管 Web 控制台却几乎是一片绝对的空白。“拥有了最快的引擎，却只能手敲几百行 JSON 发动它？”面对这处生态断层，alireza0 再次推开了代码编辑器。[4][5]

第三幕 · 拓荒 S-UI：前后端解耦与全景规则画布

2024 年 2 月 13 日，alireza0 正式在 GitHub 推送了 S-UI 的初始代码，宣告了首个专为 sing-box 定制的现代化 Web 控制台诞生。

吸取了传统面板“前后端紧耦合、改动动辄牵一发而动全身”的教训，alireza0 展现出极具前瞻性的架构设计：他建立了独立的 s-ui-frontend 仓库，以前端工程化体系构建现代化仪表盘；后端则采用高性能 Go 语言直接与 sing-box 核心通信。

S-UI 原生解析并映射了 sing-box 的 Inbound、Outbound 与 Route 规则集。用户不仅能在直观的 Web 表单中一键开启 Shadowsocks 2022、VLESS、Trojan、TUIC 与 Hysteria2，还能实时监控每个用户的实时流量曲线，并一键生成兼容 Clash、Shadowrocket、Sing-box 的原生订阅与二维码。[4][6][5]

第四幕 · 双轨守望：极简主义的跨时代回响

同时维护两套底层哲学截然不同的面板系统，对任何开源开发者而言都是一场严酷的精力拉锯战。但 alireza0 却展现出惊人的自律与技术专注。

在接下来的两年里，他保持着双轨并进的稳定迭代。一方面，他于 2026 年 8 月推出 X-UI v1.12.0，持续完善 Xray 最新字段的兼容性与轻量 SQLite 数据库迁移；另一方面，他在 9 月推送 S-UI v1.6.3，紧密对齐 sing-box 核心的路由行为修正，并提供覆盖 Linux 与 Windows 的双架构二进制分发包。

在他的个人博客与仓库文档中，始终醒目地标注着“仅用于个人学习与网络技术研究”的克制声明。从补齐 X-UI 的流控短板，到开拓 S-UI 的可视化先河，alireza0 以一人之力为全球数万名服务器管理者铺平了通往下一代网络技术的坦途。[3][7]

代表作品与核心贡献

S-UI

访问作品

基于 sing-box 核心的现代 Web 管理面板，采用前后端解耦架构，提供可视化规则编排与多格式订阅输出。

X-UI

访问作品

面向 Xray 的轻量多协议多用户管理面板，支持基于 IP 数量的精准流控、到期限制与 Telegram 交互告警。

alireza0：3x-ui 连接池在 Xray 重启后受 gRPC backoff 影响恢复延迟
