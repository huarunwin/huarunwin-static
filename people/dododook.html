所见即所得的极速体验：FlowZ 与 sing-box 毫秒级调度艺术

追求零 spawn 起核、Windows TUN 极限提速与拓扑可视化，重塑现代桌面代理的性能基准

时代与桌面客户端起核迟钝的困境

Windows 等桌面系统由于复杂的 UAC 权限隔离、网络适配器注册延迟以及外部进程拉起开销，导致很多基于现代内核的 GUI 客户端在点击启动 TUN 模式后需要漫长的加载等待，甚至因偶发 UAC 超时而频繁误报启动失败，严重损伤了交互的即时反馈感。[1]

破局与设计哲学：拓扑可视化与所见即所得

dododook 坚持将“敏捷响应与所见即所得”置于设计核心。他为 FlowZ 构筑了优雅直观的拓扑视图，用户不仅能一目了然看清流量在入站、规则、代理组与出站之间的流转，更能在拓扑图上通过右键直接将访问域名快速固定到特定策略组中。[1][2]

硬核工程深水区：Windows TUN 起核从 12.1s 到 4.4s 的极限压榨

在 2026 年 8 月，dododook 展开了著名的起核性能专项攻坚。通过细致分阶段埋点，他在 commit 9043125 中记录：“perf(win-tun): Windows TUN 起核 12.1s → 5.2s（分阶段埋点 + 五处优化）”；随后在 commit d7aba78 中进一步优化：“perf(win-tun): Windows TUN 起核 5.2s → 4.4s（netsh 探测 + 解析器并行 + 地址预检改懒执行）”。

最后在 commit e0902e8 中达成终极目标：“perf(win-tun): 起核就绪窗内零 spawn + coreReady 埋点细分”，彻底消除了起核过程中的子进程派生开销，让 Windows 桌面代理进入了秒级就绪的崭新时代。[3]

时代余响与历史地位

FlowZ 树立了开源代理客户端在桌面工程性能调优与现代视觉审美结合上的新典范，其对内核起核耗时的毫秒级拆解分析成为了社群传阅的性能优化范本。[1][2]
