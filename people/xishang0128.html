从代理工具积累到 Sparkle：一条跨客户端的开源参与轨迹

收获近 8,000 星标，以严谨自洽的技术执念串联 Sparkle、Clash Party 与全平台深度适配

第一幕 · 荒野探针：从 Root 模块、规则集到订阅工具的极客积淀

2023 年春，在纷繁复杂的网络代理生态外围，开发者 xishang0128（汐殇）开始在 GitHub 留下踏实而敏锐的技术足迹。

面对当时 Android 系统日益严格的沙盒管控与后台网络断连，他先后开源并维护了面向 Root 玩机的 clash-for-magisk 模块，以及精细化分流规则库 clash-rules；随后，进一步针对现代订阅转换生态研发了 sub-store-template 模板库与通用格式转换工具 convert；

这一阶段的工具实践虽多以个人探索和极客场景为主，却让他在规则解析、订阅流编排以及底层路由转发等深水区积累了深厚的实战功底，为日后在桌面客户端领域的技术爆发奠定了坚实基石。[19][20][21][22]

第二幕 · 跨界巡航：穿梭于主流客户端核心的协同修补

2023 年底代理生态大震荡后，Mihomo（Clash.Meta）体系全面崛起，跨平台客户端面临多重架构兼容挑战。xishang0128 开始以纯粹的技术贡献者身份，穿梭于各大核心开源项目的修复前线。

2024 年 4 月，他在桌面主流客户端 Clash Verge Rev 中提交关键修复：

「fix: Allow core files in specific directories to be upgraded normally」

解决了受限目录环境下核心文件无法正常静默升级的系统级难题。紧接着，他的工程足迹跨越至移动端巨擘 Clash Meta for Android（CMFA）：不仅参与基础依赖库版本合并，更重构了 Proxy.kt 与 Provider.kt 的核心状态流；

在随后的工程演进中，他更进一步主导将 CMFA 的庞大订阅信息抓取逻辑完全下沉至 Go 语言底层实现，彻底消除了移动端在频繁解析大订阅时诱发的内存抖动。这种跨越桌面与移动端底层的协作实践，展现了他对系统级代理机理的透彻洞察。[9][10][13][11][14]

第三幕 · 宿命分叉：从 Clash Party 破土而出的自用方舟

2024 年夏天，基于现代化 Electron 架构的新兴桌面客户端 Clash Party 迅速崭露头角，其优雅的交互设计令人耳目一新，但面对深度极客玩家的多样化定制诉求，主干分支依然存在难以调和的节奏分歧。

2024 年 8 月 5 日，xishang0128 做出了一次坚决的技术选择：他正式从上游代码库分叉（Fork），拉开了独立演进客户端 Sparkle 的序幕：

「update common options (#2)」

在项目诞生之初，xishang0128 展现出了难能可贵的清醒与坦率。他在 README 中将项目直白地定位为“Another Mihomo GUI”，并写下了一段极具极客个性的独立宣言：

「本项目为自用，绝大部分 pr 可能都不会合并。」

这绝非故步自封的傲慢，而是一名资深极客对代码主导权、架构纯粹性与精神自洽的郑重宣誓。[2][4][5]

第四幕 · 双向反哺：在独立演进中守护上游血脉

与开源领域中许多“分叉即决裂、老死不相往来”的割裂态势不同，xishang0128 在精心打磨 Sparkle 的同时，始终与上游公共仓库保持着紧密且温暖的协同纽带。

他把在 Sparkle 中经过实战验证的通用架构补丁，源源不断地反哺给 Clash Party 官方主干：2024 年底，他提交了更详尽的连接细节（Connection Details）监测面板；2025 年春，攻克并修复了复杂的 Proxy-Provider 加载时序 Bug；

而在 2025 年底，当上游遭遇内嵌 Sub-Store 单页应用（SPA）历史回退路由失效的棘手难题时，他再次挺身而出提交关键修补，彻底解决了单页内嵌容器在 Electron 中的导航死锁；

这种既守护个人项目自由度、又对上游公共资产报以高度敬畏的技术操守，赢得了整个开发者社区的由衷认可。[16][17][18]

第五幕 · 极客熔炉：Sub-Store 聚合与国产龙芯 LoongArch 远征

在 Sparkle 的硬核工程深水区，xishang0128 将其打造成了一座功能高度聚合的“极客瑞士军刀”。

应用不仅深度内嵌了功能强大的 Sub-Store 订阅聚合工作台，免去用户额外部署容器服务的繁琐成本，更原生整合了 WebDAV 多端云同步、动态配置覆写（Override）与智能流量统计面板，实现了开箱即用的闭环网络中枢；

而在硬件架构适配层面，xishang0128 更展现出了极其罕见的广谱执着：Sparkle 不仅全面覆盖 Windows 与 macOS 双主流架构，更在 Linux 平台构建了涵盖 DEB、RPM 与 Arch PACMAN 的完整发布管线；

他攻克了 MIPS 架构的 TUN 虚拟网卡堆栈，更原生攻坚了国产龙芯 LoongArch64 架构的依赖覆写与编译补丁，让先进的网络分流工具首次流畅运行于国产自主指令集芯片之上。[7][6][5]

第六幕 · 时代余响：近八千星标与自由自洽的极客样本

截至 2026 年秋，Sparkle 在 GitHub 上斩获了近 8,000 颗星标，伴随着 1.26.9 版本向 HeroUI 3 的现代化视觉跃迁，这款自用起步的客户端展现出了惊人的工程生命力。

在波澜壮阔的代理客户端编年史中，xishang0128 提供了一种极其珍贵且真实的开源样本：

他不追逐虚妄的商业宣传，不堆砌未经验证的性能神话，始终恪守公共技术的严谨事实与代码边界；

用公开的 Git 提交串联起从外围规则、移动端核心到桌面客户端的漫长轨迹，在代码的世界里实现着一名工程师最纯粹的创造自由与精神自洽。[1][7][23]
