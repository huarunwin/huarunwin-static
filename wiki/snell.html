Snell

翻墙应用商店 · 2026-11-09 · 更新于 2026-11-20

代理协议v6.0.0 正式版

条目导读

Snell 是 Surge 团队设计的轻量加密代理协议，重视性能、部署便利、结构化错误回报与完整 TCP 语义。Snell 6.0.0 已正式发布：官方于 2026-10-19 宣布将 RC2 转为最终的 6.0.0，更新下载链接，并新增 macOS arm64 二进制。正式版公告

阅读路径：概览 → 版本与机制 → 可核验节点 → 兼容性 → 配置与升级 → 安全取舍 → 来源。

01 · 概览与正式版状态

项目 已核验内容
开发团队 Surge 团队；相关应用见 Surge
官方服务端 独立二进制和配置向导；Linux 仍依赖 glibc
v6 当前状态 6.0.0 正式版，2026-10-19 官方确认
基础传输 TCP；v3 起支持 UDP over TCP；v5 另有针对 QUIC 的 UDP 路径，v6 已移除 QUIC Proxy Mode
v6 主要变化 从 PSK 自动派生部署级协议配置与流量整形，新增 mode 和服务端网络栈控制
源码边界 官方二进制分发与 Mihomo 的开源兼容实现分别记录

Snell 将远端错误回报给客户端，便于区分认证失败、目标连接超时等情况。官方设计介绍还强调完整 TCP 状态机，包括半关闭语义。单文件分发简化部署，但不能据此写成完全没有系统依赖，或将官方二进制服务端说成已开源。版本说明设计介绍

状态与日期辨析

2026-06-12 的设计文章描述当时的 Beta 阶段，随后有 RC1、RC2，至 2026-10-19 的后续公告明确转为 final 6.0.0。本次核验时，发布页、代理配置手册仍有 Beta 字样；当前正式版状态以这条后续的明确公告为依据，不把旧文案继续当作当前测试版状态，也不单凭下载文件名判断发行状态。正式版公告

02 · 版本演进与 v6 机制

各版本分别增加什么

版本 官方说明中的变化 兼容边界
v1 轻量部署、性能与结构化错误回报 旧版连接语义与后续版本分开核对
v2 连接复用 Surge 手册说明 v2 总是复用，v1/v3 不复用；v4 起另有 reuse 开关
v3 UDP 转发 支持 UDP over TCP
v4 在 AES 加密流中引入受控扰动 与 v6 的部署级协议配置区分
v5 动态记录大小、QUIC Proxy Mode、出口控制与 Socket Activation 动态记录大小属于服务端优化；v5 服务端兼容 v4 客户端，后者不启用 QUIC Proxy Mode
v6 PSK 派生协议配置、mode、dns-ip-preference、多地址 listen 已正式发布；移除 QUIC Proxy Mode；历史 Beta 与正式版兼容性需分别核对

以上是机制演进顺序。当前引用页面未为每个旧版本给出可核验的精确发布日期，因此这里不补写日期。版本说明配置手册设计介绍

PSK 派生的部署级协议多样化

官方设计介绍称，v6 的协议配置包含 42 个特征参数和 13 类填充、流量整形策略，影响帧、填充、包长分布和流量组织。客户端和服务端从相同 PSK 自动派生对应配置；不同 PSK 产生不同部署特征，无需手工复制一套底层参数。设计介绍

这种设计用于减少对单一协议特征的依赖。它不模拟 TLS 或其他现有协议，设计说明也不能替代独立的真实网络抗识别测试。

v5 的 QUIC 路径与 v6 的移除

v5 的 QUIC Proxy Mode 只在 Surge 识别到 QUIC 流量时启用，使用 UDP over UDP；服务端需要开放相应 UDP 端口。官方说明该模式强加密并认证 QUIC 握手，后续已由 QUIC 自身加密的数据包按原包转发；其他 UDP 流量仍经 TCP。版本说明配置手册

v6 不再支持 QUIC Proxy Mode。官方设计文章说明此前实际效果未达到预期，并建议在多数代理场景中阻止 QUIC，让应用回退到 HTTP/2 over TCP；这是官方建议，不是所有网络条件下的实测结论。移除该专用模式不等于完全无法通过通用 UDP 隧道承载 QUIC 数据。设计介绍

04 · 客户端与内核兼容性

软件或实现 v6 支持依据 使用时需核对
Surge iOS / Mac 客户端 手册列出 iOS 5.20.0+、Mac 6.7.0+ 显式配置 version=6；两端协议版本及 mode 一致。配置手册
Snell Server 独立程序 6.0.0 正式版公告 当前官方列出 Linux amd64、i386、aarch64 与 macOS arm64；按架构选择包，不猜测未列出的包名。版本说明正式版公告
Surge 内置 Snell 服务端 内置服务端手册支持 version=1 / 6，v6 标注 Mac 6.8.0+ 在 [Snell Server] 中显式设置 version=6；省略时默认 v1。客户端与服务端的起始版本分别记录。内置服务端手册
Mihomo v1.19.34 明确加入 v6 outbound + inbound 核对实际内核、配置入口和订阅转换；文档列有 version: 6、mode 及可选 userkey。Mihomo 配置发行说明
其他图形客户端 逐一核对对应发行包 支持 Snell 或采用 Mihomo，不足以证明已支持 v6

Snell 的协议版本与 Surge、Mihomo 的软件版本是不同编号体系。手册列出的最低客户端版本，也不表示任意历史 Beta 均可与当前服务端互通。

05 · 配置与升级

Surge 客户端

[Proxy]
Snell-v6 = snell, server.example, 7177, psk=REPLACE_WITH_SERVER_PSK, version=6, mode=default

主机和 PSK 是占位值。PSK、协议版本和 mode 必须与服务端一致；省略 version 时 Surge 默认旧版 v1，因此应显式声明。v6 不使用旧 obfs、obfs-host 或 obfs-uri 参数，流量整形从 PSK 派生。配置手册

v6 的三种 mode

mode 加密与整形 适用边界
default AES 加密及 PSK 派生流量整形 常规部署默认选择
unshaped 保留 AES 加密，关闭流量整形 不包含默认模式的流量整形能力
unsafe-raw 关闭加密与流量整形，明文转发 仅限调试、受保护内网或已有安全隧道；不提供机密性

客户端与服务端必须使用一致的 mode。在 Surge 中给低于 v6 的策略设置 mode 会导致配置错误。版本说明配置手册

独立服务端网络栈

dns-ip-preference 控制 DNS 结果的地址族选择，可取 default、prefer-ipv4、prefer-ipv6、ipv4-only、ipv6-only。listen 支持多个逗号分隔的监听地址，例如：

listen = 0.0.0.0:7177,[::]:7177
dns-ip-preference = prefer-ipv4

这两项是独立服务端配置，不是 Surge 代理策略参数，也不直接作为 Surge 内置服务端配置使用。配置手册设计介绍

Mihomo 客户端

proxies:
  - name: snell-v6
    type: snell
    server: server.example
    port: 7177
    psk: REPLACE_WITH_SERVER_PSK
    version: 6
    mode: default
    udp: true

示例依据文档展示 v6 出站字段。userkey 是另列的可选 v6 ClientID，不假定为所有官方服务端都必须配置的认证项。Mihomo 的 obfs-opts 还支持其他外层组合，属于需另行核对的实现能力，不等同于 Snell v6 自带 TLS 伪装。Mihomo 配置

升级前核对客户端、服务端和转换器支持范围，保存现有可用配置，再让两端使用一致的版本、PSK 与 mode。配置示例是文档示范，不代表已完成实际服务端部署。

06 · 安全取舍与适用边界

官方说明 Snell 使用认证加密，并为降低开销有意不提供前向保密或专门的重放保护，PSK 派生参数也侧重计算成本。官方建议使用向导生成的 32 字符随机 PSK。版本说明

流量整形、连接复用与低握手开销分别解决不同问题，不能据此宣称绝对安全、不会被识别、固定内存占用或普遍优于其他协议。unsafe-raw 不提供加密；希望优先获得更完整安全保证时，官方建议考虑基于 TLS 的代理协议。版本说明
