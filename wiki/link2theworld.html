条目导读

Mint Ryu 使用 GitHub 账号 Link2theWorld 维护 Mintyx。该项目是面向个人与亲友的 Xray 自托管面板，配套本地 SSH 部署器。

本文依据固定提交、发行材料与个人 README，区分面板、部署器、内核和自动发布账号的角色。

02 · Mintyx 的技术工作

02.1 · 个人面板的起点：把部署与第一条线路连起来

Mintyx 当前保留的根提交于 2026 年 11 月 22 日以“feat: start MintYX as an independent Xray panel”为题，实际 GitHub 作者账号为 Link2theWorld。提交和随后保留的源码展示了单管理员面板、Xray 配置及本地部署器；这只能确定可见项目历史的起点，不代表开发者此前没有相关工作。

README 将项目介绍为“一个人用的 Xray 面板，带一键部署器”。用户在自己的电脑上填写 SSH 连接信息，部署器上传面板并配置服务；管理面板默认监听服务器的 127.0.0.1:8088，通过 SSH 隧道访问。Windows 和 macOS 出现在部署器下载列表，实际面板环境仍是使用 systemd 的 64 位 Linux。

来源：Mintyx 根提交：独立个人 Xray 面板；固定发行提交的功能与系统要求；部署器、SSH 隧道与构建说明。

02.2 · 访客与配额：月度重置不替代管理员的手动停用

11 月 22 日的功能提交把界面中的“客户”改称“访客”，说明使用者是管理者的亲友。配额从一次性总量扩展为可选的月度周期，重置日可以设为每月 1 至 31 日，短月份使用月末。源码区分因额度耗尽而暂停与管理员手动停用：新周期可解除前者，保留后者。

同一提交补充管理员密码重置命令。提交说明指出密码只在部署时展示一次，丢失后不应以清空数据库为代价恢复访问；重置记录审计，并让旧密码对应的内存会话失效。这些是已公开的实现取舍，不能替代独立安全审计。

来源：访客、月度配额、密码恢复、出口链与线路图提交；固定版本的功能范围和数据外送边界。

02.3 · 出口链与本机记录：把转发路径和观测边界展示出来

Mintyx 将访客、入站线路、出口代理和互联网放入可视化线路图，线路可经一组出口转发。对应提交同时包含出口链接解析、配置生成和路由图实现；这建立的是面板与 Xray 的集成关系，不把 Xray 内核或相关协议的原创贡献归给面板维护者。

攻击页从本机 sshd journal 与 Xray 输出汇总来源，来源记录在最后出现三十天后清理。RDAP 查询默认关闭，启用后注册机构会看到被查询 IP 与服务器地址。连通性检测也默认关闭，启用时使用 Globalping，后者会获得服务器地址；Hysteria2 的 UDP 端口不能由该检测直接验证。生成举报信只提供草稿，由用户决定发送。

来源：访客、月度配额、密码恢复、出口链与线路图提交；攻击记录、RDAP 与举报草稿实现；固定版本的功能范围和数据外送边界。

03 · 项目与部署生态

Mintyx 面板与部署器

Mintyx 服务端条目登记 v0.1.0，许可证为 GPLv3。服务器要求 systemd Linux amd64 或 arm64，使用 root 或可 sudo 账号安装；本地部署器分别提供 Windows amd64、macOS universal 和 Linux amd64 下载。它们帮助安装与访问服务器，不是代理连接客户端。

北京时间 11 月 23 日的构建提交把部署器整理为 Windows、macOS 和 Linux 下载，并用 lipo 合并 macOS 两种 CPU 架构。v0.1.0 的 Release 附带这三类文件与 SHA256SUMS.txt；服务器面板的 amd64、arm64 程序由构建脚本嵌入部署器。Release 发布账号是 github-actions[bot]，与代码提交署名分别记录。

来源：固定发行提交的功能与系统要求；部署器、SSH 隧道与构建说明；三类部署器的正式打包与发布流程；Mintyx v0.1.0 正式 Release 与下载资产。

与 Xray 的关系

Mintyx 的公开工作集中在面板、配置与部署集成。使用 Xray 不意味着参与 Xray 内核开发，也不建立本站客户端作者关联。本站登记其已核验的服务端作品，不借个人 README 中的其他项目链接扩展未经审计的贡献年表。
