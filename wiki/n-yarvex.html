nyarvex 是 GitHub 账号 n-yarvex 公开使用的名字，维护 Nakis 协议及 Go 参考实现、sing-nakis 适配库与 nakis-killer 分析工具。其公开工作涵盖顺序复用、UDP 扩展、TLS 认证绑定，以及对自身协议 NAP 记录特征的样本分析。

1. 公开技术身份

仅记录该公开账号的技术作品和可归属提交；日期按北京时间整理。项目 Telegram 作为仓库来源保留，不当作个人发言账号；不推断现实身份、单位、地域或未证实的上游合作。样本测试不等于抗审查结论。

2. 协议与参考程序

Nakis 的完整仓库历史从 2026 年 11 月 8 日的初始提交开始。参考程序以共享 UUID 认证，在本地提供 SOCKS5，并在服务端连接目标；干净隧道可在业务结束后回到连接池，供下一会话顺序复用。

11 月的 udp.go 提交加入 UDP 隧道实现。源码没有图形界面或系统 VPN，平台构建目标和 Android 客户端的界面能力分别由各项目记录。

3. 面向 sing 的适配库

sing-nakis 的初始提交位于 11 月 14 日，README 公开客户端和服务端 API，并说明 TLS exporter 绑定对标准库 TLS 的要求。它是供宿主集成的库，其服务器目标交给宿主路由处理。

README 明确写道：“nor are any claims made about detection (censorship) resistance.” 作者报告的 Linux 测试范围与实际下游集成分别确认；SakuraBox 自带适配，不能据仓库互链认定它使用该库。

4. 对 NAP 特征的公开分析

nakis-killer 包含 TLS 记录采样中继、Python 分析器和公开 JSONL 样本。README 记录六条已使用隧道命中、二十条未使用预热连接未命中及六条 HTTP/1.1 对照连接未命中。

这组材料可以说明作者分析了自身实现的短记录特征；样本数量、连接状态和脚本条件必须一起阅读，不能转写为通用检测率或实际封锁事实。动态填充 NAP 在该仓库中是改进建议。
