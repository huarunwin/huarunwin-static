词条概览与核心定位

01

在 2012 年之前，中国网民翻越防火长城（GFW）主要依靠传统的通用网络协议（如 SSH 动态端口转发、PPTP、L2TP/IPSec 或 OpenVPN）。 这些传统企业协议在设计之初均面向内网穿透与办公加密，其握手具有固定的数据包头与明文协商特征，极易被防火墙通过深度包检测（DPI）定点丢包阻断。

clowwindy 的革命性创举在于：彻底抛弃传统协议的所有握手流程与固定标识！Shadowsocks 客户端与服务端只需事先约定一个密钥，首个数据包直接用随机初始向量（IV）或盐（Salt）将请求加密， 使得整个 TCP/UDP 流在中间路由看来，完全呈现为毫无规律的高熵（High-Entropy）随机二进制流。

此后，Shadowsocks 启发并衍生出了整个现代翻墙生态（包括 ShadowsocksR、V2Ray、Trojan、sing-box 等）。 尽管由于 GFW 机器学习对“未知无特征纯密文”的封锁收紧，裸奔的 Shadowsocks 直连常遭干扰， 但作为各类高级前置伪装（如 ShadowTLS）与内网穿透工具的底层承载，它依然是整个生态最核心的基础设施。

定位结论

Shadowsocks 是现代翻墙技术不可动摇的开山鼻祖与精神图腾。 在专线网络（如 IPLC/IEPL）中，AEAD Shadowsocks 凭借极低的额外头部开销、超高并发吞吐与极致简单，始终是各大商业机场的首选骨干协议。

SOCKS5 密文与 AEAD 原理

02
1. 本地 SOCKS5 代理接口层（Local Proxy Listener）在用户设备本地提供标准的 SOCKS5（1080）或 HTTP 代理端口， 让浏览器、操作系统及各类应用程序无需感知底层加密，透明发起网络请求。
2. AEAD 认证加密与抗重放校验层（Authenticated Encryption）弃用不安全的纯流密码；采用 AES-256-GCM 或 ChaCha20-Poly1305，每一个数据分块均附加认证标签（Tag）， 一旦中间人篡改或重放，服务端立即校验失败并丢弃，防御主动探测。
3. 远程透明分发与目标重连层（Remote Dispatcher）服务端解密获得真实目标地址（IPv4 / IPv6 / 域名），由服务端直接向目标服务器发起真实的 TCP 握手或转发 UDP 数据报。

AEAD 传输状态与数据交互

  1. 客户端生成随机 Salt 并派生子密钥使用 HKDF 算法结合用户密码派生出会话专用的子密钥，确保每次连接的密文均不重复。
  2. 发送加密的目的地址与载荷大小先发送长度与长度的 AEAD 认证标签，再发送目标地址（域名或 IP）与端口。
  3. 服务端核验 Tag 并解密目的主机服务端使用共享密钥派生相应子密钥并解密；若 Tag 校验失败直接断开，阻断重放扫描。
  4. 双向全双工密文传输后续所有 TCP 数据均切分为独立带 Tag 的数据块进行安全双向透明流转。

为什么它至今仍被专线青睐？

在不经过公网 GFW 的内网专线（IPLC / IEPL）上，不需要伪装成网页； Shadowsocks 的协议头开销几乎为零，CPU 加解密效率远高于复杂的 TLS，能跑出极致满速与超低延迟！

适用场景与网络边界限制

05

最推荐使用场景：

  • 国内直连专线（IPLC / IEPL / 游戏加速线）：不经过 GFW 审查直接点对点传输，享受最纯粹的极低延迟与超大吞吐。
  • 路由器与极低硬件设备：C 语言版（libev）和 Rust 版常驻内存极小，老旧嵌入式设备首选。
  • 配合 ShadowTLS / V2Ray 插件：作为强大的内部加密层，由外层插件解决 TLS 伪装。

不适用或受限场景：

  • 敏感时期裸奔直连公网 VPS：未经混淆的纯密文流易被基于机器学习的流量分析模型识别并限速甚至阻断端口。

特征识别对抗与现代搭配建议

06

1. 严禁使用任何流密码（Stream Ciphers）：如 `rc4-md5`、`aes-256-cfb` 等已被证明容易受到主动重放探测而暴露特征， 必须使用带有 AEAD 校验的 `aes-256-gcm`、`chacha20-ietf-poly1305` 或 `2022-blake3-aes-128-gcm`。

2. 公网直连自建建议：在普通的非专线公网 VPS 上部署时，建议优先搭配 ShadowTLS v3 前置伪装， 或者直接选用 VLESS REALITY。
