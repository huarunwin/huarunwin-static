Trojan + TLS

经典 HTTPS 伪装鼻祖 · 主动探测透明回落 · 跨平台客户端无死角支持

由 GreaterFire 于 2017 年首创提出[1]，放弃传统的对称密文混淆思路，直接伪装成互联网最常见的合法 HTTPS 流量。 客户端与服务端进行标准的 TLS 握手[2]，在加密隧道内校验密码； 遭遇未授权连接或审查防火墙主动探测时，透明回落（Fallback）至真实 Web 服务器（如 Nginx 或 Caddy）[3]。 奠定了现代翻墙协议防御主动探测的基础范式。

词条概览与核心定位

01

在 2017 年之前，翻墙工具普遍采用 Shadowsocks 类的“纯密文随机流”模式。然而随着机器学习算法在 GFW 的部署， 缺乏标准协议头、熵值（随机度）极高的非标准流量极易被统计学模型定点标记并进行重放或探针扫描。

Trojan 逆向思考：最安全的方式不是隐藏特征，而是表现得毫无特征。 它完全假借真实 Web 站点的身份，使用标准 443 端口与合法的 CA 证书进行 TLS 1.3 握手。 更为关键的是其透明回落（Pass-Through）机制：当防火墙使用探测脚本扫描服务器端口、或者审查员直接在浏览器打开域名时， Trojan 服务端会将其悄无声息地导向真实的 Web 服务，展示正常的博客或企业主页，彻底打消了审查系统的怀疑。

定位结论

Trojan + TLS 是翻墙技术发展史上最具里程碑意义的协议之一。尽管后续的 REALITY 免除了域名配置、Hysteria 2 强化了弱网， 但 Trojan 凭借极高的稳定性与全平台所有客户端 100% 支持的成熟度，至今仍是所有机场与自建用户最信赖的保底协议。

标准 HTTPS 与透明回落原理

02
1. 标准 TLS 1.2 / 1.3 加密包装层外层完全是符合 RFC 8446 标准的 TLS 握手，拥有合法机构签发的证书链； 在网络嗅探器看来，与全球数十亿正规 HTTPS 银行或电商网站没有任何二致。
2. 紧凑的密文认证与路由协议帧（Trojan Header）解密后的内层仅包含 56 字节的密码 SHA-224 十六进制哈希串以及目标请求地址； 无多余的对称协商开销，认证成功后双向流量无损透传。
3. 探测透明回落网关（Fallback Gateway）首包校验未通过或接收到非标准 Trojan 帧时，服务端不报错不断流， 直接透明转发给本地 Nginx / Caddy 的 80/8080 端口，返回真实的静态网页。

握手与回落详细流程

  1. TLS 客户端 ClientHello 握手客户端发起正常的 TLS 握手，携带自备域名的 SNI 标头，完成证书验证。
  2. 解密 Trojan 头部认证服务端在 TLS 隧道内读取第一包数据，匹配密码 SHA-224 哈希值。
  3. 分支 A：合法用户正常代理密码匹配成功，服务端根据目标地址发起 TCP/UDP 远程连接，开始转发数据。
  4. 分支 B：恶意探测透明回落密码错误或为常规 HTTP GET 请求，直接交由后端 Web 服务响应，表现为正常网站。

回落设计的重大意义

在 Trojan 之前，被探测的代理服务器通常会直接超时丢包或发送 RST 中断； 而这种“与普通网站不同的异常网络响应”恰恰成为了 GFW 封锁的铁证。 Trojan 的回落彻底消除了这一统计学异常！

适用场景与网络边界限制

05

最推荐使用场景：

  • 全平台多设备混用与保底备用：拥有老旧设备（旧款路由器、电视盒子、Surge 老版本）时的万能兼容协议。
  • 拥有正规自备域名与建站需求：前置搭建真实个人博客或静态官网，既能正规建站又能隐蔽代理。
  • 纯 TCP 端口环境：标准 443 端口在绝大多数封锁 UDP 的企事业单位网络中均可无障碍连接。

不适用或受限场景：

  • 不想购买自备域名的用户：必须自备合法域名并申请配置有效证书（此场景更推荐 VLESS REALITY）。
  • 极高丢包率普通网络：由于纯基于 TCP 传输，弱网抢带宽能力不如 Hysteria 2。

证书要求、嵌套 TLS 隐患与局限性

06

1. 证书有效性至关重要：客户端必须开启证书校验（allowInsecure=false）， 若允许不受信任的自签证书，中间人防火墙可发起伪造证书阻断并确信该服务为翻墙代理。

2. 内部嵌套 TLS 特征（TLS in TLS）：当用户通过 Trojan 访问外部 HTTPS 网站时，外层是 Trojan 的 TLS，内层是用户目标站点的 TLS。 若不使用 XTLS 类似流控，在特定握手阶段会暴露出内层 TLS ClientHello 的长度特征，这是后来 Project X 研发 XTLS Vision 的动力之一。
