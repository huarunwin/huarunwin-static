VLESS + XHTTP + TLS

翻墙应用商店 · 2026-11-08 · 更新于 2026-11-08

代理协议独立百科词条CDN 反代首选

新一代 CDN 反向代理传输 · 上下行解耦 · 彻底解决 WebSocket 痛点

由 Project X 团队核心作者 rprx 设计提出[1]，作为传统 WebSocket 与 gRPC 传输方式的现代化演进。 将单条长连接解构为标准的 HTTP 分块传输（Chunked Transfer Coding）[2]， 支持独立的上传流与下载流（stream-up / packet-up）。 不仅完美契合 Cloudflare 等商业 CDN 的缓存与连接调度机制[4]， 更成为拯救已被 GFW 封锁 IP 的 VPS 节点的首选终极武器。

词条概览与核心定位

01

在翻墙对抗史上，“套 CDN”一直是一种保命型方案：将真实 VPS 隐藏在大型公共 CDN（如 Cloudflare）之后， GFW 即使封锁也只能封到 CDN 节点。过去，实现 CDN 翻墙主要依赖 WebSocket（WS） 或 gRPC。 然而，商业 CDN 针对 WebSocket 有着严格的长连接保持上限（如定期中断连接、限制并发流大小）， 且 WebSocket 在中间网关容易产生双向缓冲积压，导致高延迟与断流。

Project X 团队在 2024 年秋季推出的 XHTTP（Extensible HTTP） 从根源上颠覆了这一现状[5]。 它不依赖特殊的协议握手升级，而是完全模拟标准浏览器请求：通过独立的 HTTP POST/GET 流进行分块传输（Chunked Transfer）， 使流量在外层 CDN 和防火墙看来，完全就是普通的动态 Web 页面或媒体流拉取， 彻底消除了传统 WS 的连接特征与边缘排队限制。

定位结论

VLESS + XHTTP + TLS 是当今配合 CDN 拯救被墙 VPS、或需要隐藏服务器源站 IP 时的最优首选组合。 它彻底替代了陈旧的 VMess+WS，具备更低的延迟、更高的可靠性与真正的现代 Web 兼容性。

上下行解耦与 XHTTP 原理

02

**1. 协议轻量代理层（VLESS）**移除了 VMess 复杂的对称加密与时钟验证开销，仅负责用户身份识别（UUID）与目的地址解析， 全权交由外层标准 TLS 保证前向机密性。

**2. 上下行解耦传输通道（XHTTP stream-up / packet-up）**将上行数据与下行数据拆分为独立的 HTTP 流；支持通过 HTTP/2 多路复用并行发送分块 Chunk， 绕过 CDN 对单个单向大包的审查拦截，实现无损平滑穿透。

**3. 边缘反向代理与 CDN 优选 IP 层（Cloudflare Edge / Anycast）**客户端与 CDN Anycast 节点建立标准 HTTPS 443 连接；真实 VPS 隐藏在 CDN 之后， 用户即使服务器 IP 已遭 GFW 阻断，仍可通过优选无污染的 CDN 边缘节点满速中继。

XHTTP 数据流转交互过程

  1. 客户端发起标准 HTTP 请求向 CDN 域名发送带有合法 Host 头的 HTTPS 请求，协商标准 HTTP/2 或 HTTP/3。
  2. 上下行分离分块传输上行数据通过 HTTP POST Chunked 发送；下行数据通过 HTTP GET 持续流式响应接收。
  3. CDN 边缘智能回源转发CDN 将两路标准 HTTP 流透明代理至背后的真实 VPS 服务器，源站 IP 完全对外界隐匿。
  4. 服务端 VLESS 状态还原Xray 服务端将两路 HTTP 数据块重新拼装为双向 TCP/UDP 代理流，完成外部目标转发。

为什么它优于 WebSocket？

WebSocket 在 CDN 体系中属于“非标准二等公民”，常遭遇边缘网关频繁的超时断连、连接数配额压制； 而 XHTTP 是纯粹的 IETF 标准 HTTP，享有与正常网页浏览完全同等级别的 CDN 调度优先级与传输通道！

适用场景与网络边界限制

05

最推荐使用场景：

  • **拯救被墙 IP 的服务器：**VPS IP 被 GFW 封锁后，挂载到 Cloudflare 等 CDN 之后即可瞬间“复活”满血可用。
  • **配合 CDN 优选 IP 加速：**通过脚本筛选延迟最低、未被丢包的 CDN 官方节点 IP 作为客户端连接目标，大幅改善劣质外网宽带体验。
  • **隐藏服务器真实源站：**用于对外公开的节点或多用户服务，完全防止源站 IP 被直接探测定位或遭遇 DDoS 攻击。

不适用或受限场景：

  • **要求毫秒级低延迟的竞技网游：**由于必须经过 CDN 边缘节点的中转二次握手，整体延迟比直连方案高 30~80ms。
  • **必须自备域名：**配置 CDN 反代必须拥有一个解析至 CDN 的独立域名，无法像 REALITY 那样做到免域名使用。

CDN 优缺点权衡与配置建议

06

**1. CDN 规则匹配与回源模式：**建议在 CDN（如 Cloudflare Dashboard）中开启 WebSockets 支持与 gRPC 开关（即使使用 XHTTP，部分边缘功能共享策略通道）， 同时关闭针对代理路径的缓存与安全验证挑战（如 Managed Challenge / WAF 防火墙误杀）。

**2. 客户端模式选择建议：**在移动端弱网环境下，建议优先选择 stream-up 模式以降低连接建立开销； 而在某些对长连接管控极为严苛的特种局域网下，可选用 packet-up 模式实现更细粒度的包分段。
