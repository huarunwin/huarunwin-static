Trojan (Trojan Protocol)

真实证书 TLS 握手 · 成为标准 HTTPS · 主动探测 Fallback 回退

Trojan 是由开源组织 GreaterFire 于 2017 年设计的著名代理协议[1]。 面对审查防火墙对自定义混淆协议层出不穷的针对性识别，Trojan 提出了颠覆性的逆向思维：「模仿协议总是会留下破绽，唯有真正成为标准协议才能完全免于针对」。 它直接架设在合法的公网域名与真实权威 CA 证书之上，监听标准的 443 端口； 当遭遇未知探测流量时，服务端会自动执行 Fallback（回退） 呈现合法的真实网站，是合规自建 HTTPS 代理的经典标杆[2]。

词条概览与核心定位

01

在 ShadowsocksR 等混淆协议遭遇深度学习分类器的大规模阻断后，审查者通过主动探测手段向疑似代理节点发送伪造的握手数据包， 若服务端返回非标准响应或直接断开连接，就会被立刻标记封锁。

Trojan 优雅地解决了主动探测难题：客户端首先与服务端完成标准、真实的 TLS 握手； 握手成功后，客户端发送一段经过 SHA-224 散列的 56 字节定长密码校验串与代理请求。 如果收到未经认证的连接、普通浏览器访问或是防火墙的探测探针，Trojan 服务端绝不断开连接， 而是将数据流透明转交给后端的 Nginx 或 Caddy 服务，向探测者返回标准的合规网页内容[1]， 使审查者在统计学与行为学上均无法将其与普通网站区分。

定位结论

Trojan 属于标准 HTTPS 代理的成熟标杆。 由于其完全遵循标准 TLS 规范，不易引起机房云厂商的风控误杀，是拥有独立公网域名用户的常青首选。

真实 TLS 握手与 Fallback 回退架构

02
1. 标准 TLS 1.2/1.3 加密承载层使用真实权威 CA 签发的合法域名证书，严格遵循 RFC 标准完成 TLS 协商； 所有外部网络特征与正常访问大型知名 HTTPS 网站完全一致。
2. SHA-224 密码校验与定长请求原语在安全通道内，客户端发送 56 字节的密码十六进制哈希与 CRLF 换行符； 协议自身结构极简，避免了复杂协商产生的往返延迟。
3. 主动探测智能 Fallback 回退机制校验失败或检测到标准 HTTP 请求时，服务端直接短接本地 Web 容器（如 Nginx/Caddy）； 探测者只能看到正常搭建的博客或企业主页，彻底消除代理指纹暴露风险。

握手与回退交互生命周期

  1. 标准 TLS 握手协商：客户端发起 ClientHello，双方完成证书验证并协商出会话对称密钥，建立安全隧道。
  2. 首包密码摘要校验：客户端在加密通道内送达 SHA-224 密码摘要；服务端在常数时间内校验密码真伪。
  3. 代理转发或智能回退：合法请求被代理出站至真实网络；非法探测或正常网页请求被静默回退给本地网站容器呈现。

域名与证书维护要求

Trojan 依赖合法的域名与有效证书。若证书过期、域名解析失效或被 DNS 污染， 客户端握手校验将直接报错中止，需要自建者配置自动续期（如 acme.sh / certbot）。

适用场景、网络边界与部署建议

05

最佳适用场景

自有合规域名的建站兼翻墙：适合个人开发者在 VPS 上同时部署真实博客主页与翻墙代理； 全平台跨平台极高成熟度：iOS、macOS、Windows、Android 甚至路由器均具备第一方原生支持； 标准 443 端口网络环境：在仅开放 Web 端口的严格办公内网中，通过标准 HTTPS 伪装可轻松穿透。

网络边界与安全注意事项

必须自备域名与有效证书：不能使用自签名或过期证书，否则现代客户端安全验证会直接阻断连接； 注意 SNI 阻断与证书指纹关联：若自建域名仅从特定 IP 获取大流量，存在 SNI 被定向封锁的可能； 建议务必配置合理的本地 Fallback：若不配置回退，遭遇扫描探针连接直接中断，失去 Trojan 的主动防御特性。
