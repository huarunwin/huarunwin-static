EasyTier

Serverless Mesh · 零依赖去中心化拓扑 · 自动多跳中继选路 · 子网代理

由开源社区于 2023 年基于 Rust 语言发起的纯去中心化点对点虚拟网状局域网协议[1]。 彻底摆脱对任何第三方云端账号或中心化协调控制服务器的依赖， 节点之间通过对等分布式拓扑算法自动发现、打洞并组织成加密虚拟子网； 支持多协议承载（UDP / TCP / WebSocket / WireGuard）与多跳自动中继选路，被越来越多技术人员用于私有网络互通与代理出口中继[2]。

词条概览与核心定位

01

在当今主流的异地组网方案中，Tailscale 依赖集中式的协调控制面（若使用自建 Headscale 仍需自行运维长常驻服务）， 而传统的 VPN 工具在复杂的 NAT 打洞与多路径网络选择上缺乏灵活性。 部分注重隐私和完全自治的技术团队渴望一种“真正的去中心化（Serverless）”组网体验： 任何节点只要知道网络名称与密码，并且知道网络中任意一台已有节点的地址，即可瞬间加入网络，无需注册账号、无需依赖任何云端[1]。

EasyTier 应运而生，采用现代化 Rust 语言从零构筑： 所有节点均为对等（Peer-to-Peer）关系。当两台设备处于不同 NAT 后面时，项目会自动发起 UDP 端口打洞； 若打洞受阻，网络中处于最优公网位置的节点会自动充当数据包的中继转发者， 全程无感知切换，并利用 ChaCha20-Poly1305 或 AES-GCM 实现真正的端到端加密保护[2]。

定位结论

EasyTier 是新一代极简自托管异地组网的代表作。 尽管其诞生时间较短，但因其完全开源、单二进制文件、无任何商业绑定的去中心化纯粹性， 正在迅速成为技术人员打通跨国多云服务器链路与实现异地代理转发的黑马武器。

去中心化对等网与自动中继架构

02
1. 全对称去中心化拓扑 (No Central Controller)完全剔除中央协调服务器概念；网络拓扑依靠节点间的心跳与分布式路由表（Kademlia DHT 思想）进行邻居发现与自组织扩张[1]。
2. 多传输承载层 (UDP / TCP / WebSocket / WireGuard)在严苛运营商或封锁环境中，EasyTier 支持将底层流量伪装为标准 TCP 甚至 WebSocket 协议流，规避激进的 UDP 丢包限制[3]。
3. 智能多跳中继与子网代理 (Subnet Proxy)任意节点可声明代理自己身后的整个局域网段（如 192.168.1.0/24），其他节点无需在每一台终端安装客户端即可直接访问目标内网设备。

去中心化入网与通信流程

  1. 节点启动与对等握手：执行单一命令启动，指向一个公网对等点（Peer URL），完成网络名与密码核验。
  2. 全网拓扑感知与智能打洞：节点接收邻居广播的拓扑图，按需向目标节点发起直连穿透测试，优先建立 P2P 高速直连。
  3. 路径质量评估与动态切换：持续测量链路延迟与丢包率，直连出现抖动时瞬间切换到低延迟中间节点中继，保持通信不中断。

代理生态集成与翻墙出口实践

Mihomo 等现代代理内核已将 EasyTier 作为 Outbound 节点类型支持。 用户可以在海外云主机上运行一个轻量 EasyTier 实例作为网络节点， 在国内客户端通过配置文件直接将该节点指定为出站出口，享受全去中心化的代理体验[4]。

适用场景、网络边界与部署建议

05

最佳适用场景

零外部依赖自建私网：不愿注册任何商业账号、避免任何第三方服务器留存网络拓扑元数据的自托管用户； 嵌入式与轻量单板设备：内存只有几十兆的微型路由器或树莓派，单二进制文件开箱即用； 多云多机房内网穿透：分布在阿里云、腾讯云、AWS 与海外 VPS 之间的跨云专线级免配互通。

网络边界与安全注意事项

新兴项目成熟度：项目诞生于 2023 年底，面对极端复杂蜂窝移动网络的穿透算法仍处于持续演进阶段； 初次启动依赖种子节点：去中心化网络至少需要有一台节点拥有公网可达 IP，或借助公开的公共对等节点作为首个发现入口； 无针对 GFW 的深度伪装：虽然支持 TCP/WS 封装，但默认数据流并非针对审查系统做深度主动探测防御，跨境直连仍需注意流量特征。
