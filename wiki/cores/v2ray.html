条目导读

V2Ray（现由 V2Fly 维护）是较早把代理协议、传输、路由和二次开发组织成模块化平台的 Go 核心。它保留 VMess 等传统组件，也提供 VLESS、Shadowsocks、Trojan、DNS 和透明接管能力；今天的 V2Ray、V2Fly 与 Xray 是不同版本线，不能用“支持 V2Ray”替代具体核心版本。

阅读路径：按“概览 → 核心能力/技术贡献 → 时间线或版本 → 生态与来源”阅读；事实、版本与判断均以正文标注的公开来源为准。

02 · 核心架构与能力

模块化核心如何组织连接

V2Fly 的配置把 inbound、outbound、routing、policy、transport 和 app 分开：入口协议接收本地或服务端连接，路由规则把请求送到出站，transport 与 streamSettings 再决定 TCP、WebSocket、gRPC、HTTP/2 或 QUIC 等承载。这样可以替换一个入站或出站而不改写整套路由，但配置对象仍需与所用发行版版本匹配。

来源：https://github.com/v2fly/v2ray-core/blob/b53bebbb859f2970e99432d53047a1bb8620e987/README.md

VLESS、VMess 与其他出站并存

V2Fly 的 proxy 配置包含 VMess、VLESS、Shadowsocks、Trojan、SOCKS 和 HTTP 等入站/出站实现。VLESS 的鉴权、传输和 TLS 参数与 VMess 不同；Xray 后续增加的 Vision、REALITY 或 XHTTP 不能因为项目存在分叉关系就自动写回 V2Fly。

来源：https://github.com/v2fly/v2ray-core/blob/b53bebbb859f2970e99432d53047a1bb8620e987/proxy/vless/outbound/config.proto

DNS、FakeDNS 与透明代理

app/dns 提供本地、UDP、TCP、DoH、DoQ 与 FakeDNS 组件，app/tun 和 dokodemo-door 可把系统流量交给路由器。DNS 查询选择和业务连接选择仍是不同的规则过程；透明代理能否工作还受操作系统路由和权限限制。

来源：https://github.com/v2fly/v2ray-core/blob/b53bebbb859f2970e99432d53047a1bb8620e987/app/dns/config.proto

v5.53.0 的变化

截至本轮核验，V2Fly 稳定版为 v5.53.0。发行说明列出基于 Stream 的 UDP Packet Addr、会话压缩/恢复，以及 socks5ify 工程命令；这是该版本新能力的来源，不能据此宣称所有图形客户端已经提供对应开关。

来源：https://github.com/v2fly/v2ray-core/releases/tag/v5.53.0

V2Fly 与 Xray 的边界

Xray-core 的官方说明把 v1.0.0 标为从 v2fly-core 特定提交分叉。两者保留部分配置概念和协议名称，但发行节奏、实现和新增传输已经分开；页面中的应用关联只表示应用声明使用该核心，不表示两个项目共用当前二进制。

来源：https://github.com/XTLS/Xray-core/blob/676eaf66f8f05d4d558ee7a74b4736623d3feeb9/README.md#credits
