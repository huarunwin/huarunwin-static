liandu2024：Open-Box「真实路由」探测误报源于响应头过大与内核 DNS 解析，v0.1.318 已修复

在 Open-Box issue #583（反馈「Gemini 能打开，但规则页「真实路由」提示访问失败」）中，liandu2024 说明这是规则页「真实路由」探测自己的问题，不影响实际访问，分流本身没问题（规则路由与真实路由的出口一致）。两种测法各有一处：「模拟终端」探测只收 16 KB 以内的响应头，而 gemini.google.com 的响应头约 26 KB（其中一条安全策略头就将近 20 KB），超过即报「response headers too large」，浏览器没有该限制所以能正常打开；已改成响应头超限时仍保留已解析到的 HTTP 状态码并按状态码判断结果，避免仅因响应头过大误报。「内核诊断」解析时没有按终端的方式问内核的 DNS，开着 FakeIP 时走代理的网站拿到的地址不对，一测就失败；已改成和终端一样向内核的 DNS 入口查询，并加上 GET / HEAD / TCP / TLS 的选择。作者称 v0.1.318 已发布、升级即可，本 issue 关闭，并请反馈者升级后重测。

作者原文@liandu2024

这是规则页「真实路由」探测自己的问题,不影响实际访问,分流本身没问题(规则路由和真实路由的出口是一致的)。两种测法各有一处:

  • 「模拟终端」:gemini.google.com 返回的响应头有 26 KB 左右(一条安全策略头就将近 20 KB),探测程序只收 16 KB 以内的响应头,超过就报「response headers too large」;浏览器没有这个限制,所以能正常打开。已改成响应头超过限制时仍保留已经解析到的 HTTP 状态码，并按状态码判断结果，避免仅因响应头过大误报。
  • 「内核诊断」:解析时没有按终端的方式问内核的 DNS,开着 FakeIP 时走代理的网站拿到的地址不对,一测就失败。已改成和终端一样向内核的 DNS 入口查询。另外内核诊断也加上了 GET / HEAD / TCP / TLS 的选择,和模拟终端一样。

v0.1.318 已发布,升级即可。本 issue 关闭。
