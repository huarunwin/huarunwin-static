Own716 频道对比 sing-box、Mihomo 与 Xray-core 的适用场景

OwnBox 官方频道（Own716）2026-09-27 10:03:01Z 发帖，逐一对比三个内核并给出他自己的倾向： sing-box：后台资源占用低、吞吐量很强、TUN 很强、新协议支持非常全面，UDP / QUIC / Hysteria 2 / TUIC 等优势明显，长时间运行适合，Android 原生适配成熟；他特别提到 sing-box 1.15.0 起 sing-tun 使用自有 TCP/IP 协议栈，官方称峰值性能、能效与内存占用相比此前实现都有明显改进。追求「手机后台常挂 + 省内存 + 高速下载上传 + TUN 全局代理」时他更倾向 sing-box。 Mihomo：他称为 Clash 系生态的主力内核，稳定性好、规则分流成熟、Clash YAML 生态丰富、占用也低、日常省心；主要使用 Clash 订阅、大量规则、国内外分流、Fake-IP、复杂 Rule Provider 时更有优势。 Xray-core：最大优势仍是 VLESS + REALITY + Vision 这套成熟生态，节点主要是 VLESS / REALITY / Vision / VMess / Trojan 时依然值得用；若要全能型 Android 内核（Hysteria 2、TUIC、QUIC、WireGuard、复杂 DNS / TUN 等），他认为 sing-box 覆盖面更适合。 以上为频道作者的选型观点，不涉及任何版本发布或行为变化；其中 sing-tun 自有 TCP/IP 协议栈一项此前已随 sing-box 1.15.0 与 OwnBox v2.8.0 的公开说明收录。

频道原文@OwnBoxs

其他内核推荐原因

  1. sing-box

后台资源占用：低
吞吐量：很强
TUN：很强
新协议支持：非常全面
UDP / QUIC / Hysteria 2 / TUIC 等：优势明显
长时间运行：适合
Android 原生适配：成熟
尤其值得注意的是，sing-box 1.15.0 开始，sing-tun 使用了自己的 TCP/IP 协议栈。官方明确表示，相比以前的实现，在峰值性能、能效和内存占用方面都有明显改进。
Sing Box +1
所以如果你追求的是：
“手机后台一直挂着 + 尽量省内存 + 高速下载/上传 + TUN 全局代理”
我目前更倾向于 sing-box。

  1. Mihomo

Mihomo 本质上是现在 Clash 系生态的主力内核。
优点：
稳定性很好
规则分流非常成熟
Clash YAML 生态非常丰富
后台资源占用也比较低
日常使用非常省心
如果你主要使用：
Clash 订阅
大量规则
国内外分流
Fake-IP
复杂 Rule Provider
那么 Mihomo 很有优势。
不过如果单纯追求新协议 + 高吞吐 + TUN 性能 + sing-box 生态，sing-box 更符合你的需求。

  1. Xray-core

Xray 最大的优势还是：
VLESS + REALITY + Vision
这套生态非常成熟。
如果你的节点主要是： VLESS REALITY Vision VMess Trojan
Xray 依然非常值得用。
但是如果你想要的是一个全能型 Android 代理内核，需要 Hysteria 2、TUIC、QUIC、WireGuard、复杂 DNS/TUN 等能力，那么 sing-box 的覆盖面更适合。
