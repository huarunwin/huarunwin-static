官方变更日志

The 4.15.0 preview line lands as a stable release: the connections/dashboard fixes, the
single-node import and REALITY corrections, the Bettbox toolbox and the subscription-card
additions, plus one vocabulary and brand pass over the app's own code.

Fixes

- The route card's edit and menu buttons no longer drift. They were vertically centred against the whole card, so the remote detail line that arrives after the list (and the update bar while a profile refreshes) moved them down with the card's height. They now sit on the title row, where the card's growth cannot move them; a layout test pins the action button to the title's centre.
- Every bulk event was zero bytes. Flutter 3.50's StandardMessageCodec.encodeMessage returns its buffer positioned after the bytes (it allocates, writes and returns without a flip); BulkWire read from that position, so the connections list and the logcat feed were always sent as an empty payload. The original symptom was a bare Message corrupted; after 4.15.1 started dropping undecodable frames the connections page simply stayed empty. The encoder now normalises the buffer (flip only when nothing remains) and a JVM test decodes the produced bytes with the same codec, which also checks there is no trailing garbage.
- An empty connections list now says why, and can fix itself. The page asks the host for connections.state: a stopped tunnel is named as such, a switched-off Clash API gets a one-tap Enable (it writes the port and reloads the core), and an enabled-but-silent API shows its address, port and HTTP error with Retry. The host skips the request entirely when the API is off and keeps the poller's last failure for the state.

- A bad bulk frame is dropped, not shown as "Message corrupted". The byte payloads of the connection and log feeds are copied when they arrive (the codec hands back a view into the event envelope), a frame that does not decode is skipped with one diagnostic per feed instead of a banner per tick, and the host no longer sends an empty bulk frame when a value encodes to nothing. The next 1.5 s tick rebuilds the connection list, so a single bad frame costs one refresh.

- A single-node import ends on the node page. The profile form no longer asks for a target group — the host always puts a single imported node into the single-node container, so the question only blocked the save — and it switches to the node page before the sheet pops.
- Editing a single node keeps its protocol. A bare typed outbound is parsed as one node instead of being wrapped as a Custom configuration, so saving an edited node no longer changes its type.
- A node selected outside the proxies page survives a reopen. The proxies page replayed its own per-configuration memory over the host's selection, which reverted a node picked on the single-node page (or by a notification) as soon as that configuration was shown or the app was reopened. A native selection that is not the group's first member is trusted and written into the memory, and the node page records its pick there too.
- REALITY derives the auth key from the standalone X25519 share. Xray and sing-box REALITY servers take the key from the ClientHello's standalone X25519 share when one is present and only fall back to the X25519 half of the hybrid X25519MLKEM768 share otherwise; Xray's client selects the same way. The extended kernel's previous choice preferred the hybrid's key whenever ML-KEM was advertised first, which diverges from every reference server. A failed verification now also logs which share was used.
- REALITY works with fingerprints that predate ML-KEM. Xray-core v26.9.8+ REALITY servers reject a ClientHello without the hybrid X25519MLKEM768 key share. Only the Chrome presets offered it, so a REALITY node set to firefox, safari, ios, edge, android, 360 or qq (or random when it picked one of them) received the fallback certificate and reported "reality verification failed" with hybrid share present: false. That fingerprint's ClientHello now gains the group and the key share, keeping everything else it defines; Chrome keeps its untouched fast path, TLS-1.2-only presets and randomized/custom fall back to Chrome, and the failure log names the fingerprint beside the two shares.
- A second "Default" group is adopted instead of duplicated. A document whose last group was deleted gets a group with no stored name; it renders with the localized default label, but the single-node container check only compared the stored name, so the first import created a flagged "Default" beside it and the pickers listed both. An unnamed local group now counts as the container (an import backfills its flag), and the node page removes extra empty containers, keeping the one that holds nodes.
- The network toolbox speaks the app's language. The Bettbox cards rendered their titles from the English keys directly; they now go through the translation table, so 测速 / 连通性测试 / 流量统计 / 节点测试 replace "Speed test" / "Connectivity test" / "Traffic statistics" / "Node tests" (and the two settings cards likewise).
- The tool sheets are Prism forms, not bare lists. A bare bottom sheet still reserves the compact sheet bar's height, which showed as a large empty forehead above the first section; each tool's settings now open as a titled form sheet with the standard close button, and the traffic sheet likewise.
- The node editor no longer offers Multiplex. The section and its derived state were removed from the outbound editor (an existing multiplex object in a node's JSON is left untouched). The TLS fragment row is a switch now instead of a text field, matching the boolean the model stores.
- The proxies page owns "Clear test results". The profile card's long-press menu loses that entry, along with "Clear traffic statistics" and "Group settings"; the proxies page's own overflow menu clears the visible configuration's test results.
- Subscription cards show what is left. The quota line reads Remaining 87.7 GB · Expires Nov 30, 2026; a subscription the provider did not date reads … · Permanent, an unlimited provider shows Remaining Unlimited, and a local profile still shows no quota line.
- An unnamed subscription names itself. The add/edit form no longer requires a name for a subscription: a new one takes the server's Profile-Title, then its URL host (www. dropped); an existing one whose name was cleared falls back to the URL host.

Changes

- The connectivity card is a service-status card. A header with the verdict chip ("All available" / "N failed") and the refresh button, then a two-column grid of up to four pinned services, each cell carrying its artwork, name and latest result — latency, limited/flagged, not unlocked or failed. The full page is still one tap away.

- The network toolbox is a Bettbox-style card grid. The one-column settings list became a 92 dp card grid with wide and tall cards, icon boxes and watermarks, press tint, and each tool's settings in a sheet; the switches, traffic store and exit detection behind them are unchanged.

- One vocabulary in the app's own code. The Dart presentation, document and controller layers now call the two concepts by the UI's names — Configuration for a profile card and Node for a proxy entry — and the Kotlin sources carry the Flrone brand (Bbox/ThroneBoxBridge files and classes became Flrone/FlronePlatformBridge, bboxmodel became flronemodel). The compatibility boundaries stay untouched: profiles.json, the profiles.platform op, every wire/settings key, the FFI throne_* symbols and the Android package ids. docs/naming.md records the vocabulary and the boundaries.

- The About page's version and licence badges are the entries. Tapping the version badge checks for updates and the GPL-3.0 badge opens the licence page; the separate "Check for updates" button and the "Open-source licenses" row are gone. The credits name B-box for the early migration approach and Bettbox for the detailed feature reference.

- The kernel link points at the maintained fork. The About Core row and all three READMEs link yuedaochangmendian/sing-box-ext (Throneproj's base plus VLESS encryption, XHTTP, mKCP and REALITY); the credits keep the upstream sing-box entries.

Features

- Traffic statistics, the whole chain. A new Tools page records traffic from the core's cumulative totals and attributes it with a host-side poller: the connection list is read every five seconds, each connection's delta is split by proxy/direct and attributed to its destination, node, rule and app, and the app merges the deltas into a daily ledger (hour buckets, per-profile split, bounded maps). The page follows the reference layout: an enable switch (off by default), day/week/month with previous/next navigation, a total ring with upload/download and the proxy/direct split, rule hits, a domain/node ranking with site icons, and a settings sheet (record details, website icons, 7/30/90-day retention, clear data). A core restart re-baselines instead of counting a negative delta; the ledger persists every five minutes and on a lifecycle pause.

中文说明

4.15.0 预览线转为正式版：连接/仪表盘修复、单节点导入与 REALITY 修正、Bettbox 网络工具箱、订阅卡片增强，以及一次覆盖自有代码的词汇与品牌整理。

修复

- 路由卡片的编辑/更多按钮不再漂移。 它们此前相对整张卡片垂直居中，列表加载后才到达的远程信息行、以及刷新时出现的进度条都会让卡片变高，按钮随之向下漂移。现在按钮固定在标题行上，卡片内容增长不会再移动它们；新增布局测试把动作按钮钉在标题中线。
- 所有 bulk 事件都是 0 字节。 Flutter 3.50 的 StandardMessageCodec.encodeMessage 返回的缓冲区位置在字节之后（分配、写入后直接返回，没有 flip）；BulkWire 从当前位置读取，导致连接列表与 logcat 流永远以空载荷发出。最初表现为裸的 Message corrupted；4.15.1 改为丢弃无法解码的帧后，连接页就只剩下空列表。编码器现在会归一化缓冲区（仅在无剩余时 flip），并新增 JVM 测试用同一编解码器解码产物（同时验证没有尾部垃圾）。
- 连接列表为空时会说明原因，并可一键修复。 页面向宿主查询 connections.state：隧道未运行会直接说明；Clash API 被关闭时给出一键「启用」（写入端口并重载内核）；已启用但无响应时显示地址、端口与 HTTP 错误并提供「重试」。宿主在 API 关闭时不再发请求，并保留轮询器最近一次失败原因供状态展示。
- 坏帧被丢弃，而不是显示「Message corrupted」。 连接与日志的字节载荷在到达时先复制（编解码器返回的是事件信封的视图），解码失败的帧按每种流只记录一次诊断、不再每个周期弹一次横幅；宿主在编码结果为空时也不再发送空帧。下一轮 1.5 秒采样会整表重建连接列表，单个坏帧的代价只是一次刷新。
- 单节点导入会落在节点页，并在重启后保持选中。 配置表单不再要求选择目标分组（宿主总会把单个导入节点放进单节点容器），并在表单关闭前切到节点页；代理页不再用旧的按配置记忆覆盖宿主选择，节点页也会写入同一份记忆。
- 编辑单节点会保留原协议。 裸的 typed outbound 会作为单个节点解析，而不是被包装成 Custom 配置，保存后类型不再改变。
- REALITY 使用独立 X25519 share 派生 auth key。 Xray 与 sing-box 服务端在 ClientHello 同时带独立 X25519 与 hybrid X25519MLKEM768 时，使用独立 share 派生密钥；内核之前优先 hybrid，与参考实现不一致。现在按 Xray 客户端的顺序（Ecdhe 优先，缺失才用 MlkemEcdhe），失败日志会写明使用的 share。
- REALITY 支持早于 ML-KEM 的指纹。 Xray-core v26.9.8+ 服务端要求 hybrid X25519MLKEM768 keyshare；只有 Chrome 预设自带。firefox / safari / ios / edge / android / 360 / qq（或 random 抽到它们）会收到 fallback 证书并报 reality verification failed。现在会向这些指纹的 ClientHello 补入该 group 与 keyshare，其余保持不变；纯 TLS 1.2 预设与 randomized / custom 回退 Chrome，失败日志附带 fingerprint。
- 重复的「默认」分组会被接管而不是新建。 文档在最后一个分组被删除时会补一个无名分组，它显示为「默认」但旧检查只比较存储名，导致首次导入又建一个带标记的「默认」。现在无名本地分组也算单节点容器（导入时补 flag），节点页会清理多余的空容器，保留有节点的那个。
- 网络工具箱说应用的语言。 Bettbox 卡片标题此前直接渲染英文 key；现在走翻译表，测速 / 连通性测试 / 流量统计 / 节点测试替换英文（两个设置卡同样）。
- 工具设置页使用 Prism 表单，而不是裸列表。 裸 sheet 仍预留 compact bar 的高度，形成首个分组上方的大片空白；现在每个工具的设置都以带标题的表单 sheet 打开，带标准关闭按钮，流量设置同样。
- 节点编辑不再提供 Multiplex。 段落及派生状态已移除（节点 JSON 里已有的 multiplex 对象保存时原样保留）；TLS fragment 行现在是开关，而不是文本框。
- 代理页接管「清除测试结果」。 配置卡长按菜单移除该项，以及「清除流量统计」和「分组设置」；代理页右上角菜单可清除当前配置的测试结果。
- 订阅卡片显示剩余量。 配额行显示 剩余 87.7 GB · 到期 Nov 30, 2026；无到期日显示「永久」，无总量显示「剩余 无限」；本地配置仍不显示配额行。
- 未命名订阅会自己取名。 订阅名称不再必填：新订阅取服务端 Profile-Title，其次 URL 主机（去掉 www.）；已有订阅清空名称后回退到 URL 主机。

调整

- 连通性卡片改为服务状态卡片。 头部带结论徽章（「全部可用」/「N 项异常」）与刷新按钮，下方是两列网格，最多四个固定服务；每个格子显示服务图标、名称与最近结果（延迟、部分可用/已标记、未解锁或失败）。点击仍进入完整页面。
- 网络工具箱是 Bettbox 风格卡片网格。 单列设置列表改为 92dp 卡片网格，宽卡/高卡、图标盒与水印、按压着色，每个工具的设置放在 sheet 里；背后的开关、流量存储与出口检测不变。
- 自有代码统一一套词汇。 Dart 展示/文档/控制器层按 UI 名称称呼两个概念：配置卡 = Configuration，节点 = Node；Kotlin 源码使用 Flrone 品牌（Bbox/ThroneBoxBridge 文件与类改为 Flrone/FlronePlatformBridge，bboxmodel → flronemodel）。兼容边界保持不变：profiles.json、profiles.platform op、所有 wire/设置键、FFI throne_* 与 Android 包名。docs/naming.md 记录词汇与边界。
- 关于页的版本号与许可证徽章就是入口。 点版本号检查更新，点 GPL-3.0 打开许可页；原来的「检查更新」按钮与「开源许可」行删除。致谢写明 B-box 提供早期迁移思路、Bettbox 提供细节功能参考。
- 内核链接指向维护中的 fork。 关于页 Core 行与三份 README 都指向 yuedaochangmendian/sing-box-ext（Throneproj 基座 + VLESS Encryption/XHTTP/mKCP/REALITY），致谢保留上游 sing-box。

应用介绍

基于 Throne 的 Android 代理客户端，使用 Flutter 界面与 sing-box、Xray 内核，支持订阅管理、路由配置、自动选优、WebDAV 和桌面备份互通。

适用于 Android 7.0（API 24）及以上设备，项目提供 Android TV 适配。需要自行导入节点或订阅；Clash 格式仅有限兼容，导入订阅只读取节点，不继承其中的路由规则。
