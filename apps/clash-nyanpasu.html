官方变更日志

简体中文版本请展开页面底部的「简体中文」。

2.0 is the first stable release since the 1.6 series. It rewrites the frontend, rebuilds how the backend manages state and the core, and adds traffic analytics, Profile pipeline inspection, a standalone widget, diagnostics and crash reporting.

These notes compare against v1.6.1. Implementations that landed during the Beta and RC cycle and were later replaced are not listed separately.

Read Before Upgrading

- Your configuration is migrated automatically. On first launch, the old verge.yaml, profiles.yaml and related files are split and migrated into new per-domain configuration files. The configuration directory and storage.db are backed up before migration; if migration fails, the startup dialog offers "Open backup directory", "Open migration log" and "Quit". Old settings keep their meaning wherever possible: for example, autocloseconnection: false becomes "Do not close connections when switching proxies", and a non-random mixed port becomes a fixed port. We still recommend backing up the configuration directory by hand before a major upgrade; afterwards, you can create a backup from Settings at any time.
- Release targets are narrowed to six: x86_64 and aarch64 for each of Windows, Linux and macOS. i686 builds for Windows/Linux and Linux ARMv7 (armel/armhf) builds are no longer provided.
- The CPU must support hardware AES: x86_64 needs AES-NI (Intel Westmere from 2010 or later, AMD Bulldozer from 2011 or later); aarch64 needs the ARMv8 AES extension. Some ARM devices without it, such as the Raspberry Pi 4/5, cannot run 2.0.
- The minimum macOS version is now 12.6 (11.0 in 1.6).
- Service mode requires nyanpasu-service 2.0.1 or later. Older services are rejected by the version check rather than falling back to the old protocol; update the service from System Settings when prompted.
- port and socks-port in Profiles, Merge/Overlay and scripts are no longer passed to the core. Like mixed-port, both ports are now managed in Clash settings and are removed when unset. This prevents a subscription's own port: 7890 from taking over the mixed port (#5720).
- The Profile model has changed. "Multiple selected Profiles + Chain" is split into a single current Config plus Transforms: merging several subscriptions is expressed with a Composition Config, Merge is renamed Overlay, and the global Chain becomes Global Transform. Remote / Local are no longer Profile types but a source property of each Profile (see "Profiles and the Pipeline"). Migration converts existing data automatically.
- Clash Premium is deprecated and will be removed in a future release. It still works in this release; core management and the dashboard mark it as deprecated, and switching to it shows a notice.
- Third-party dashboards should use the HTTP external controller settings provided by the app. The core's named pipe / Unix socket control channels are allocated and authorized per instance by the runtime and are no longer a stable, customizable interface.

New Features

Redesigned Interface

- The main interface is redesigned in Material You, and the old interface has been removed. Components are built on our own @nyanpasu/ui (Radix primitives + Tailwind CSS) rather than re-theming the old pages.
- The dashboard is made of freely arranged widgets; layouts can be saved and each widget configured on its own. When the window is resized, the layout for the new size is used.
- Theming: follow the system accent color, or pick a color from the HCT palette with live preview; light / dark / follow system; custom CSS or LESS. The default theme color is #3e64a7.
- Inter Variable is bundled and the CJK font fallback order is adjusted. The page's lang attribute follows the app language, so Han characters use the glyphs of the selected language rather than the system locale.
- Responsive sidebar and narrow-window navigation, directional page transitions, per-platform title bars (Windows / macOS / Linux) and configurable window decorations. Linux no longer uses the native title bar by default.
- The title bar menus (File / Settings / Help) are now a unified menu bar with keyboard navigation and switching between open menus.
- Settings are grouped by category, and pages with many items are split into subpages.
- The About page lists open source licenses.

Traffic Analytics

The new Traffic Analytics page lets you review historical traffic and track down anomalies:

- View traffic by overview, connection path, location, device and process; rankings can be weighted by traffic or by connection count. After filtering on a dimension, its other candidates stay in the ranking for comparison.
- Traffic is recorded per Profile, bucketed by time, and expired data is cleaned up automatically. Closed connections can also be browsed page by page with filters.
- The map is shaded by traffic share. Regions are resolved with a country index bundled with the app (built from the core's geo databases), and each region shows how it was located.
- DIRECT traffic and local sources can be located by probing the public IP. The probe requires explicit consent and is never sent while TUN is enabled.
- The Rules, Connections and Traffic pages link to each other, carrying filters along, and you can return to the original page.
- Data is stored in the new time-series layer nyanpasu-tsdb (see "Architecture"). Traffic recorded during Beta/RC is imported automatically on upgrade.

Profiles and the Pipeline

- Type and source are separate: in 1.6 a Profile was one of Remote, Local, Merge or Script, and only configuration files could come from a remote subscription. 2.0 separates "what it is" from "where it comes from". Types are Config (a single configuration file, or a Composition combining several sources) and Transform (YAML Overlay, JavaScript / Lua script). The source is a separate property of each Profile and can be:
- Remote: downloaded from a URL and synced on an interval;
- Managed locally: the file is managed by the app and edited in the app;
- Linked local file: references a file of your own, either as a "symlink" (references the original file directly; on Windows this needs Developer Mode or administrator rights) or a "mirror" (keeps a copy and syncs it when the original changes).

Overlays and scripts can therefore be synced from a remote source like subscriptions, or linked to files you maintain elsewhere.
- Pipeline: Overlay, JavaScript and Lua Transforms can be attached after a Config, and Global Transforms apply to every Config. The pipeline can be reordered by drag and drop.
- Inspect: a full-height step browser shows how the configuration is generated. Each step has a snapshot, a diff against the previous step, a list of changed fields and the step's log, with the effective nodes and each step's highest log level marked. The final view matches the configuration the core actually loads. The open document tab and step filters are remembered.
- Profile folders: create folders and organize Profiles by drag and drop or a "Move to" menu; deletion can be undone.
- Preview before importing from a URL: the content is downloaded first, classified as a Config, Overlay or script from its response headers and content, and imported after you confirm the type and source.
- Redesigned Profile cards and detail pages; subscriptions show their remaining traffic quota. All subscriptions can be updated at once, with sync status and run history; the update interval is hidden when auto-update is off.
- clash://install-config deep links can specify a name and share the quick-import flow. Links are queued in the backend and imported in order once the main window has loaded, so links arriving during a page reload or before the window loads are not lost.
- Subscriptions: Remnawave HWID, syncing the Profile name from response headers, hidden proxy groups from subscription metadata, and IP hostnames in subscription URLs.
- include-all in proxy groups is expanded the way Mihomo does it and can be toggled in Clash settings.
- The generated configuration keeps the key order of the source files. 1.6 reordered top-level keys by a fixed field table, so the generated configuration did not match the layout of the source. Nested maps keep their order too, which matters to the core for fields such as dns.nameserver-policy.
- Scripts: JavaScript can import JSON/plain-text modules and built-in helper modules, runs in memory and keeps stack traces; both JavaScript and Lua have console output, and Lua keeps the original key order after processing.
- When saving fails, the error names the Profile and the file.

Proxies, Connections and Rules

- Proxies: proxy groups are listed in the sidebar, can be put in folders and reordered by drag and drop, and the layout is saved per Profile; frequently used groups can be pinned. Nodes within a group can be searched, sorted and filtered. Latency tests use each group's own test URL with a configurable timeout; node cards show recent latency history; group headers show the number of available nodes and the current selection chain (e.g. A › B › node). Health checks can be triggered for Providers. "Close connections when switching proxies" now has three levels: off / this group only / all.
- Connections: a Closed tab, configurable columns, filtering by traffic dimension and value range, connection details and totals; sorting and scrolling through large lists are faster.
- Rules: the rule list is virtualized, can be filtered by proxy, and shows each rule's current connection count and traffic.
- Providers: a new dedicated Providers page.

Core

- Adds the Meow (meow-rs) core with its own Meow Alpha channel, and Clash Rust Alpha, including Windows ARM64.
- Alpha cores read the build currently in the upstream rolling release on every update check, so the version manifest no longer points at a deleted file after an upstream update, which caused 404 downloads.
- Core updates verify the archive's SHA-256 and the binary's version; "Reinstall" is offered when an installed core cannot report its version.
- A new core management view shows the core status, the control channel (HTTP / named pipe / Unix socket) and the service mode status. The control channel can be chosen in Settings, and the view also shows the channel actually in effect.
- With the Meow core, core updates also install its bundled meow-cli and agent skill. A new AI page in Settings provides a one-line prompt you can give to an agent such as Claude Code or Codex to install the skill.
- On macOS with TUN enabled, taking over and restoring the system DNS is part of the core transaction. The original DNS is persisted before any change, so it can be restored even after the app exits abnormally.
- When several instances run at once (for example a development build and a release build), one instance no longer stops a core that another instance started through the service.
- Service mode is now a preference: the service runs the core when it is ready; when the service is not installed, stopped or incompatible, the core runs locally and Settings shows a notice. Neither startup nor saving settings installs or starts the service automatically, so no unexpected UAC prompt appears; once the service is ready again, the next startup or an explicit action uses it again.
- Local mode and service mode share the same app-managed core data directory owned by the current user, so caches stay writable after switching modes.
- On Windows the service is controlled over a named pipe. Stopping the core first sends Ctrl+C through the service, so a force-killed Meow no longer leaves adapter DNS behind. Toggling Meow's TUN alone first tries a hot update and reads it back to confirm, restarting the core only if that fails.
- TUN auto-route can be managed separately; on Unix, TUN permissions are checked and granted automatically when needed.
